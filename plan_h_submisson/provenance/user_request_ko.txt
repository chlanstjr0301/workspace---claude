[4. 논문의 내용과 논리]

완성된 학술 문장으로 작성하라.
운영 보고서나 bullet 나열을 그대로 논문처럼 붙이지 마라.

제목, 초록, 서론, 관련 연구, 문제 정의, 데이터, 방법, 평가 설계, 결과, 논의, 한계, 결론, 참고문헌, 재현 부록을 논리적으로 연결하라.

중심 연구 질문:
“기존 PCA의 경보를 보존하면서, 예측잔차의 연속 초과 조건으로 보조 경보를 추가하면 관측된 FP 증가를 억제하면서 FN을 줄일 수 있는가?”

방법에는 다음을 실제 코드에 맞춰 설명하라.
- PCA 특징·전처리·성분 수·이상 점수·보완 경로
- R5 모델 종류·입력·목표 시점·예측 지평·학습 목적·잔차 점수
- calibration의 역할과 실제 임계값
- 현재·직전 관측의 의미
- 실제 시각과 행 인덱스의 차이
- 관측 공백·세션 경계·상태 초기화
- 온라인 추론의 정보 가용 시각과 의사코드

기호를 정의한 뒤 실제 구현과 일치할 때 다음 식을 사용하라.

h_t = 1[s_t > theta]
g_t = b_t OR (h_t AND h_(t-1))

동일 평가 행에서 기존 경보를 보존하므로 FN이 증가하지 않는다는 성질은 간단히 설명할 수 있다.
그러나 이 구조만으로 FP 유지나 FPR 목표 달성이 보장되는 것은 아니다.

같은 임계값의 단일 초과 규칙보다 연속 확인 규칙의 추가 경보 집합이 작아지는 성질도 설명하라.
이를 새로운 범용 이론이라고 과장하지 마라.
시계열 의존성을 무시하고 연속 초과 확률을 p²로 단정하지 마라.

실제 기여를 구체적으로 제시하되 다음을 근거 없이 주장하지 마라.
- 세계 최초 또는 SOTA
- 통계적으로 유의한 개선
- 현장 검증 완료
- 새로운 고장 사건 발견
- 범용 고장 예측 성능

초기 자료 분할과 이후 반복 개발·평가 노출 이력을 구분하라.
V의 엄격 감소 조건을 유지 조건과 분리한 변경 이력과 이유를 설명하라.
이전 R5의 S2 탈락을 소급해 통과로 바꾸지 마라.
전체 개발 과정이 결과를 보기 전에 한 번에 사전 등록됐다고 쓰지 마라.

사건 전체를 정탐으로 바꾸는 point adjustment 또는 유리한 평가 행 제외가 있는지 확인하라.


E. 오경보와 대조 실험

같은 임계값의 연속 확인 없는 구성 FN10·FP4와 G1 FN13·FP1 사이의 손익이 정확히 설명됐는지 확인하라.

이전 임계값 G1의 FN15·FP1을 포함해 임계값 효과와 확인 규칙 효과를 분리했는지 검토하라.

FP1행이라는 결과를 장기간 현장 오경보 보장으로 확대했는지 확인하라.

FP 예산·FPR 상한·정수 반올림 규칙·시간 구간 조건을 사후 유리하게 바꿨는지는 실제 근거로 확인하라.


F. V와 통계 해석

V에서 양쪽 FN0·FP0인 유지 결과를 FN 감소의 독립 재현으로 표현했는지 확인하라.

시계열 의존성·적은 사건 수·클래스 비율을 무시한 신뢰구간이나 유의성 주장이 있는지 검토하라.

연속 확인 확률을 근거 없이 p²라고 계산하거나, 정상 calibration 분위수를 현장 FPR 보장으로 해석했는지 확인하라.

F1·F2·Accuracy·MCC가 같은 분류 건수에서 나온다는 점을 무시하고 여러 독립적인 검증 증거처럼 제시했는지 검토하라.


G. 비교 실험의 공정성

B0·G1·대조군이 다음 조건에서 공정하게 비교됐는지 확인하라.
- 동일 평가 행
- 이용 가능한 입력 정보
- 학습·보정 범위
- 시간 경계와 초기화
- 평가 규칙

서로 다른 분할·학습 예산·평가 범위의 모델 결과를 단순 순위로 묶었는지 확인하라.

필요한 비교가 빠졌다면 왜 핵심 주장 판단에 필요한지 설명하라.
무조건 많은 알고리즘을 추가하라고 요구하지 마라.


H. 구현·재현·실시간 동작

다음을 점검하라.
- R5의 예측 시점
- 미래 정보 사용 여부
- 시각과 행 정렬
- 입력 특징 순서
- warm-up과 상태 초기화
- 결측 처리
- 온라인/batch 일치
- 저장 모델 재로딩
- 패키지 밖 파일과 절대 경로 의존성
- 누락된 모델·코드·설정

입력 검사 보완본과 결과 생성 당시 코드를 혼동했는지 확인하라.

실제로 발견한 문제만 결함으로 기록하라.
이미 검증으로 해소된 의혹은 미해결 결함에 넣지 마라.


I. 서술·인용·형식

초록·제목·결론이 실험 근거보다 강한지 검토하라.

정상 자료 학습과 라벨을 사용하는 선택 과정을 모두 완전 비지도라고 표현했는지 확인하라.

문헌이 해당 주장을 실제로 뒷받침하는지, DOI와 서지가 정확한지 확인하라.

핵심 한계를 부록에만 숨겼는지, 표의 분모·단위·그림 축이 오해를 유발하는지 검토하라.


[11-4. 보고서 구성]

분량이나 단점 개수를 억지로 맞추지 마라.
근거가 있는 문제를 빠짐없이 다뤄라.

1. 검토 대상·범위·접근하지 못한 근거

2. 가장 중요한 취약점
   - 실제 존재하는 범위에서 최대5개
   - 문제와 근거, 논문의 핵심 주장에 미치는 영향

3. 쟁점별 상세 지적

4. ICML 연구 평가 관점에서의 부족한 점
   - 기술적 타당성
   - 서술
   - 중요성
   - 독창성
   네 항목을 따로 판단하라.

5. 저자가 답해야 할 핵심 질문3~5개
   - 답변이 어떤 평가를 바꿀 수 있는지 명시하라.

6. 미해결 문제와 필요한 최소 증거
   - 기존 자료로 해결 가능한 항목
   - 새 자료가 필요한 항목
   - 현 단계에서 판단할 수 없는 항목

장점 목록이나 위로하는 결론을 넣지 마라.

논문이 이미 한계를 정직하게 적었다면 “숨겼다”고 비판하지 마라.
한계를 공개했어도 남는 연구 범위의 제약을 지적하라.

특정 Reject 판정을 미리 정하거나 채택 확률을 숫자로 만들어내지 마라.
현재 증거로 ICML급 기여를 주장하기 어려운 이유가 있다면 구체적으로 작성하라.


[11-5. 모델 변경 없이 최종 원고와 정합성 유지]

검토를 이유로 모델·임계값·분할·예측을 변경하거나 신규 튜닝을 하지 마라.

앞선 지시 범위의 기록 대조·지표 재계산·필요한 최소 재현은 가능하다.
새로운 실험을 수행한 것처럼 추가하지 마라.

명백한 오탈자·수치 전사 오류·과장 문구를 원고에서 고쳤다면 수정 이력을 남겨라.

수정 후 최종 원고를 다시 대조하고 다음을 갱신하라.
- 보고서의 페이지·표·그림 위치
- 검토 대상 원고 버전과 해시
- 해결된 지적과 미해결 지적의 상태

해결된 서술 오류와 해결되지 않은 연구 한계를 구분하라.
비판을 없애려고 한계나 부정 결과를 삭제하지 마라.


[11-6. 같은 ZIP에 포함할 산출물]

reviews/ 폴더에 다음을 넣어라.

- adversarial_review_ko.pdf
- adversarial_review_ko.md
- criticism_evidence.csv
- review_manifest.json

review_manifest.json에는 검토 대상 원고와 주요 근거 파일의 해시, 검토 범위를 기록하라.

PDF는 전체 페이지를 렌더링하여 다음을 확인하라.
- 글자 겹침
- 표 잘림
- 깨진 한글
- 인용 위치와 페이지 번호

기존 research_readiness_ko.md의 요약으로 이 보고서를 대체하지 마라.

README와 START_HERE_ko.md에 다음을 추가하라.
- 적대적 보고서의 경로
- 단점 중심 자체 검토라는 성격
- 논문과 함께 읽는 순서

최종 ZIP을 다시 만들고 다음을 갱신하라.
- manifest
- SHA256SUMS
- ZIP 외부 .sha256 파일

CRC와 압축 해제 검사를 수행하고 실제 보고서 파일이 들어 있는지 확인하라.
논문과 적대적 보고서가 동일한 최종 모델·원고 버전을 가리키는지 검증하라.

최종 답변에 적대적 보고서 PDF 링크와 전체 ZIP 링크를 포함하라.

“단점 중심 자체 검토 보고서를 ZIP에 포함했다”고 명시하되, 실제 외부 심사위원이 검토한 것처럼 표현하지 마라.
