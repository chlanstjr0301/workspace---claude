### 1.2 방법

1. 공식 문서 4종을 먼저 전부 읽고 **단일 기준표(§2)**를 만들었다.
2. 각 Plan을 **문서와 독립적으로** 깨끗한 가상환경에서 재실행했다(§6).
3. 문서의 수치를 CSV에서 다시 계산했다(TP/FP/TN/FN → P/R/F1, AP, Brier).
4. 문서가 다루지 않은 반증 실험을 수행했다. 이 실험들은 `scratchpad`에서만 실행했고 저장소 파일은 바꾸지 않았다.

## 3. Plan A 감사 결과

Plan A의 주장 요약 (`docs/plan/plan A/RESULTS.md:13-27`): 최종모델 `S1_VIB + 범위규칙`, F1 0.9282 (95% CI [0.852, 0.984]), Precision 1.000, Recall 0.866, FP 0건, 파라미터 0개, BL-0 대비 유의(P=0.019), 판정 기준과 현장 운영모델(`S3_SPEC + PCA-SPE`) 분리, 오경보의 91.1%가 16,000–19,000행에 집중.

**재계산 결과 일치 확인**: `predictions.csv`에서 TP 239 / FN 37 / FP 0 / TN 2,489, F1 0.9282, AP 0.9743, AUROC 0.9901. 표의 수치는 코드 산출물과 맞다. 문제는 수치의 **의미와 선정 과정**이다.

### A-P1-01 · 최종모델을 테스트 이상 라벨로 선정했다

- **심각도**: P1 큰 감점
- **관련 문항·예상 감점**: 문항 2 (40점) 중 선정근거, −4 ~ −6점
- **공격 대상 주장**: "임계값은 이상 라벨을 전혀 사용하지 않는다"(`RESULTS.md:42`), 선정 순서 "② F1 95% CI 하한 최대"(`RESULTS.md:116`)
- **실제 증거**
  - `plan_a_submission/src/run_all.py:149-151`: `cand.sort_values(["f1_ci_lo", "FP", "n_params"], ...)`로 정렬한다. `f1_ci_lo`는 `run_all.py:72`에서 **테스트 정상 + 이상 전체**로 계산한 부트스트랩 하한이다.
  - 32개 후보 중 1위(0.852)와 2위(0.849)의 하한 차이는 0.003이다. 32개 중 최댓값을 고른 승자 편향(winner's curse)이 그대로 남는다.
  - 감사 실험(정상 테스트 블록 회전, 같은 8×4 후보, 같은 q99.9 규칙): `S1_VIB/범위규칙`의 F1 순위가 **1 → 3 → 8 → 8위**로 바뀐다(0–5k, 5–10k, 10–15k 테스트).
- **재현·반증 방법**: 아래 §6.3 스크립트 `a_rot.py`. `TRAIN/VALID/TEST` 블록을 바꿔 같은 파이프라인을 돌린 뒤 순위를 비교한다.
- **심사위원이 제기할 질문**: "선정 기준인 CI 하한은 무엇으로 계산했습니까? 테스트로 고르고 같은 테스트로 성능을 보고했다면 그것은 검증 성능입니까, 테스트 성능입니까?"
- **우승 가능성을 낮추는 이유**: 문항 2 작성요령의 핵심인 "동일 조건 비교·선정근거"에서 순환논증으로 읽힌다. 학계 위원이 가장 먼저 지적하는 유형이다.
- **최소 수정안**: (a) 선정 규칙을 **정상 데이터만으로 계산하는 지표**(정상 블록 경보 수, 검증 FP)로 바꾼다. 이상 데이터로 계산한 F1은 "보고" 지표로만 쓴다. (b) 이미 본 결과를 숨기지 말고 "이상 데이터를 보고 선정했다"는 사실과 회전 결과(1/3/8/8위)를 함께 쓴다.
- **수정 완료 판정 기준**: 선정 코드에서 `Fa`·`_pa`·`f1*` 열이 정렬 키에 쓰이지 않는다. 보고서에 블록 회전 순위표가 있다.

### A-P1-02 · "FP 0건"은 이 분할 하나에서만 성립한다

- **심각도**: P1
- **관련 문항·예상 감점**: 문항 2·3, −3 ~ −5점 (과장 표현으로 신뢰 상실)
- **공격 대상 주장**: "FPR / FP **0.0000 / 0건**"(`RESULTS.md:18`), 논문 초록 "zero false positives"(`papers/plan_a/main.tex:62`), 결론(`main.tex:526-527`)
- **실제 증거**
  - 블록 회전 시 같은 모델의 FP window: **0 / 1 / 13 / 32** (테스트 15–20k / 0–5k / 5–10k / 10–15k).
  - 임계값 분위수 민감도(같은 분할): q0.990 → FP 58, q0.995 → FP 3 (F1 0.957), **q0.999 → FP 0** (F1 0.928), q1.0 → FP 0.
  - 임계값 0.1042는 검증 window 1,468개 중 상위 약 2개로 결정된다(검증 상위 5개 점수 0.071 / 0.079 / 0.093 / 0.114 / 0.130, 모두 `corr01_x_amp`가 결정).
  - 정상 테스트 관측시간은 0.139 h다. 알람 0건의 Poisson 95% 상한은 21.6건/h이고, 8시간 근무로 환산하면 최대 약 173건이다(`run_log.txt:64-69`에 일부 기재).
- **재현·반증 방법**: §6.3 `a_rot.py`, `a_err.py`
- **심사위원 질문**: "8분 분량의 정상 데이터에서 오경보 0건을 근거로 현장에서 오경보가 없다고 할 수 있습니까?"
- **우승 가능성을 낮추는 이유**: 출제문의 핵심이 "오경보를 줄이라"이다. 오경보 0을 간판으로 걸었다가 반증되면 문항 3·4까지 신뢰가 무너진다.
- **최소 수정안**: "FP 0건"을 "이 테스트 블록(0.139 h)에서 관측 FP 0건, 95% 상한 21.6건/h. 다른 정상 블록에서는 1–32 window"로 바꾼다. 간판 지표를 전체 정상 블록 교차검증 결과로 교체한다.
- **수정 완료 판정 기준**: 보고서·발표자료·논문에 단정형 "FP 0" 또는 "오경보 없음"이 0건이고, 블록별 FP 표가 있다.

### A-P1-03 · "파라미터 0개" 주장은 사실이 아니다

- **심각도**: P1 (사실 오류)
- **관련 문항·예상 감점**: 문항 2·5, −2 ~ −3점
- **공격 대상 주장**: "파라미터 수 **0개**"(`RESULTS.md:19`), "1등이 0파라미터 규칙"(`RESULTS.md:26`), 논문 "zero learned parameters"(`main.tex:62`), 표 `|θ|=0`(`main.tex:369`)
- **실제 증거**
  - `plan_a_submission/src/models.py:201-204`: `RangeRule.fit`이 특징별 `lo_`, `hi_`(11개 × 2 = **22개 값**)를 학습한다. 여기에 검증 분위수 임계값 1개가 더해진다.
  - `models.py:187-189`의 기본 `n_params=0`를 그대로 쓴다. `LOFNovelty`(`models.py:301-312`)는 학습 window 6,021개를 전부 저장하는데도 `n_params=0`으로 표에 나온다(`model_comparison.csv` LOF 행).
  - 이 값이 선정 규칙 ④ "파라미터 최소"(`run_all.py:151`)의 정렬 키로 쓰인다.
- **재현 방법**: `model_comparison.csv`의 `n_params` 열과 `models.py` 비교
- **심사위원 질문**: "학습 범위 min/max가 파라미터가 아니면 무엇입니까? LOF가 파라미터 0개입니까?"
- **우승 가능성을 낮추는 이유**: 연구자 위원에게는 개념 오류로 보인다. 같은 표의 다른 수치까지 의심받는다.
- **최소 수정안**: "학습 파라미터 23개(경계 22 + 임계값 1), 반복 최적화 없음"으로 표기한다. LOF는 "비모수(학습표본 저장)"로 표기한다. 선정 규칙 ④를 삭제하거나 "모형 복잡도(정성)"로 바꾼다.
- **수정 완료 판정 기준**: 모든 산출물에서 "0 파라미터 / zero learned parameters"가 0건이다.

### A-P1-04 · "오경보의 91.1% 집중"은 최종모델이 아닌 최악 모델의 오경보다

- **심각도**: P1
- **관련 문항·예상 감점**: 문항 3 (15점), −3 ~ −5점

- **공격 대상 주장**: "센서 gain/offset/polarity/noise/jitter/dropout 섭동"(`plan_c_submission/README.md:33`), "C-E07/E08 완료"
- **실제 증거**
  - `pipeline.py:420-440`: 섭동은 **이상 window에만** 적용하고(`perturb(outlier_w.values, …)`), 지표는 Recall뿐이다. 정상 window에 같은 섭동을 줬을 때의 **오경보 증가**는 측정하지 않는다. 출제문의 "정상 운전변화를 이상으로 판단하는 오경보" 문제에 대한 강건성 증거가 없다.
  - 이상 window에 gain 2.0을 주면 Recall이 오르는 것(0.958 → 0.993)은 자명하다.
  - 계획서의 RQ4/C-E08 목적은 "전류 ACF 차이를 jitter로 재현 가능한가"(`README.md:78`, `:344`)다. 구현은 jitter를 이상 window에 넣고 Recall만 본다. 정상 AI2의 ACF가 jitter로 이상 수준까지 내려가는지는 검증하지 않았다. **RQ4는 미답변**이다.
  - 섭동은 fold 0, seed 42 하나에서만 수행했다.
- **최소 수정안**: 같은 섭동 그리드를 **정상 테스트 window**에 적용해 FP·경보 사건 증가를 측정한다. 이 하나의 표로 "어떤 센서 변화가 오경보를 만드는가"(문항 3)에 답할 수 있다.
- **수정 완료 판정 기준**: `robustness.csv`에 정상 측 `fp_delta`, `alarm_events_delta` 열이 있다.

### C-P1-05 · 오류분석이 공정조건별 FN·FP 집중을 다루지 않는다

- **심각도**: P1
- **관련 문항·예상 감점**: 문항 3 (15점), −3 ~ −5점
- **공격 대상 주장**: `error_conditions.csv`가 오류분석이다.
- **실제 증거**
  - `error_conditions.csv`는 `source × state` 집계 8행뿐이다(`pipeline.py:555-559`). 시간 구간·진폭 수준·상관 부호·burst 위치 같은 **조건**별 FN/FP 분해가 없다.
  - B1의 FN은 fold 2에서 크게 늘어난다(Recall 0.857 / 0.841 / 0.811, seed별). 이유 분석이 없다.
  - 어떤 이상 burst를 놓쳤는지(burst 탐지율 0.88–0.94) 식별표가 없다.
  - Plan A가 찾은 정상 구간 16,000–19,000행의 진폭 저하·상관 반전(오경보 유발 조건)이 Plan C에는 없다.
- **최소 수정안**: OOF 예측파일로 (a) 정상 FP의 행 구간 × 진폭 × corr01 표, (b) 이상 FN의 burst × 진폭 표를 만든다. Plan A의 `fp_breakdown` 방식을 최종모델에 적용한다.
- **수정 완료 판정 기준**: 제3장에 최종모델 FN/FP 조건표 2개와 상호작용(진폭 × 상관) 분할표 1개가 있다.

### C-P1-06 · 설명 감사가 자체 규칙과 모순되고, "시간형태가 핵심" 결론이 AI2와 섞여 있다

- **심각도**: P1
- **관련 문항·예상 감점**: 문항 3·5, −2 ~ −3점
- **공격 대상 주장**: "시간형태 특징군 S를 제거하면 F1 0.8273으로 하락해, 파형의 시간형태가 핵심임을 보였다"(`EXECUTION_RESULTS.md:30-31`), "counterfactual repair 기준 전역 최상위 채널은 AI0_Vibration"(`:37-38`)
- **실제 증거**
  - 계획서 규칙: "세 방법(기여도·leave-one-group-out·counterfactual)이 **일치할 때만** 주요 기여 채널이라고 쓴다"(`docs/plan/plan C/README.md:318-324`). 구현에는 기여도(①)가 없다. 채널 수리는 AI0가 1위, 그룹 수리는 S가 1위다(`explanation.csv`). 논문은 "need not agree"(`tex:181`)라며 규칙을 뒤집는다.
  - S 그룹 제거 효과에는 AI2의 S 특징 4개가 섞여 있다. **S의 AI2 4개만 빼도 F1 0.8755**(C-P0-01 표). 따라서 "진동 파형 시간형태가 핵심"과 "전류 자기상관(세션 지문)이 핵심"을 구분하지 못한다.
  - `predictions.csv`의 `top_channel_global`은 모든 행이 `AI0_Vibration`이다(`pipeline.py:549-552`). 행 단위 설명처럼 보이지만 전역 상수다.
  - 채널 수리에서 AI2를 중앙값으로 바꾸면 AI2 원신호는 상수가 되지만 이상 window의 다른 특징 경로도 함께 바뀐다. 해석이 모델 의존적이라는 점은 문서가 인정한다(`EXECUTION_RESULTS.md:37-38`). 원인 단정은 없다(양호).
- **최소 수정안**: S 그룹 제거 실험을 채널별(S_AI0, S_AI1, S_AI2)로 분리한다. `top_channel_global` 열을 삭제하거나 행 단위 기여도로 바꾼다. 계획서의 "일치할 때만" 규칙을 지키거나, 그 규칙을 철회했다고 명시한다.
- **수정 완료 판정 기준**: 설명 결론이 AI2 제외 조건에서도 유지되는지 보이는 표가 있다.

### C-P2-01 · 최종모델이 설계서의 fault score 정의와 다르다

- **심각도**: P2
- **실제 증거**: 설계는 "S + scale-invariant R, 채널별 z-normalization, 이득·오프셋 변화 후에도 유지"(`docs/plan/plan C/README.md:208-213`)다. B1은 원시 A/S/R/O(진폭·오프셋 포함, 비정규화) IF다. gain 0.5에서 Recall이 0.958에서 0.925로 떨어진다(`robustness.csv`).
- **최소 수정안**: 설계서와 구현 중 하나를 맞추고 보고서에 실제 구현만 기술한다.

### C-P2-02 · 20-sample을 쓰지 않은 이유 중 "탐지 지연 증가"는 측정되지 않았다

- **심각도**: P2
- **공격 대상 주장**: "20-sample 창은 F1 0.9837로 가장 높았지만, 탐지 지연 증가와 짧은 burst 배제, 사후 선택 편향을 피하기 위해"(`EXECUTION_RESULTS.md:28-29`)
- **실제 증거**: Plan C 코드에는 탐지 지연 계산이 없다(`evaluation.py` 전체). "짧은 burst 배제"는 계산 가능하다. 이상 burst 21개 중 10행 이상 17개, 20행 이상 13개다. w=10 고정과 20-sample 결과의 관계 자체(사후 승격 금지)는 **방향이 옳다**. 다만 등록 시점 증거가 없다(C-P1-03).
- **최소 수정안**: "지연"은 이론값(w=20이면 판정까지 1.9 s, w=10이면 0.9 s + persistence 0.2 s)으로 바꾸고, burst 잔존 수를 표로 낸다.

### C-P2-03 · 이상 burst 탐지율 0.9255는 독립 사건의 탐지율이 아니다

- **심각도**: P2
- **실제 증거**: 분모는 10행 이상인 이상 burst 17개이고, 15개 실행 평균이다. 17개 burst는 고장 1건을 2분 46초 동안 쪼갠 것이다. 문서는 "21건의 독립 고장으로 주장하지 않는다"(`EXECUTION_RESULTS.md:69-70`)고 적는다(양호). 다만 0.9255(3 seed)와 persistence 표의 0.9294(seed 42)가 같은 문서에 섞여 나온다(`:19` vs `:32`).
- **최소 수정안**: "같은 고장 기록 내 수집 구간 17개 중 평균 15.7개에서 경보"로 표현하고, seed 기준을 표기한다.

### C-P2-04 · 같은 설정의 수치가 표마다 다르다

- **심각도**: P2

### C-P2-05 · `data_audit.csv`의 결측 1건은 계산 산출물이다

- **심각도**: P2 (문항 1 데이터 진단 오류)
- **실제 증거**: `data.py:116` `df.isna().sum().sum()`이 `assign_bursts`가 추가한 `dt_seconds` 첫 행 NaN을 센다. 원본 CSV의 결측은 0이다(감사 재계산). 반면 중복 TimeStamp 1건(정상)은 감지했다.
- **최소 수정안**: 원본 열만 대상으로 결측을 센다.

### C-P2-06 · shift score에 수집 메타데이터(burst 길이·위치)가 들어간다

- **심각도**: P2
- **실제 증거**: `pipeline.py:474` `shift_idx = ("A", "O", "Q")`. Q = `burst_position_fraction`, `burst_length`(`features.py:215-218`)다. 이상 파일의 burst 길이 분포는 정상과 다르다. shift 판정이 일부 수집 방식의 지문이 될 수 있다. shift score의 A/O에도 AI2가 들어간다.
- **최소 수정안**: Q 포함·제외 두 버전의 Yellow-S 비율을 보고한다.

### C-P2-07 · "시간순 분할"이라는 표현이 정확하지 않다

- **심각도**: P2
- **실제 증거**: `data.py:133-142`에서 fold k는 test = 블록 k, calibration = 블록 k+1, train = 나머지다. fold 0은 블록 2–4(**미래**)로 학습하고 블록 0을 테스트한다. 논문은 "split normal bursts chronologically into five contiguous blocks"(`tex:119`)라고 쓴다. 블록 자체는 연속이지만 학습→테스트는 시간순이 아니다. 누수는 아니다(이상 데이터는 항상 5일 뒤).
- **최소 수정안**: "연속 블록 순환 교차검증(시간 역방향 학습 포함)"으로 바꾸고, 전방 연쇄(forward-chaining) 1개 결과를 병기한다.

### C-P2-08 · 센서 결측 정책이 문서에만 있다

- **심각도**: P2
- **실제 증거**: "AI2 채널 결측 시 Yellow-S로 강등하고 센서/DAQ 점검"(`EXECUTION_RESULTS.md:35-36`)이라고 하지만 상태 결정 코드(`pipeline.py:532-539`)에 결측 감지 분기가 없다. dropout 실험은 값을 0으로 바꾼 것이지 결측 감지가 아니다.
- **최소 수정안**: 채널 분산 0 또는 NaN 감지 → `Degraded` 상태 분기 10줄을 추가하거나, "운영 제안(미구현)"으로 표기한다.

### C-P2-09 · LSTM-AE 제외가 공식 요건에 미치는 영향

- **심각도**: P2
- **판단**: 공식 요건은 "베이스라인 포함 2개 이상"이다. B0(범위 규칙) + 4개 모델로 **형식 요건은 충족**한다. 다만 데이터셋 가이드북의 기준 알고리즘이 LSTM-AE다(`previous research/about.md:34`). 심사위원이 "가이드북 모델과 왜 비교하지 않았는가"를 묻기 쉽다. "Python 3.13에서 TensorFlow 불가"(`EXECUTION_RESULTS.md:66-67`)는 환경 선택의 결과지 방법론적 이유가 아니다. 감사 환경에서는 Python 3.11 가상환경을 문제없이 만들 수 있었다.
- **최소 수정안**: PyTorch CPU 또는 Python 3.11 TensorFlow로 같은 fold·같은 임계값 규칙의 LSTM-AE 1구조 × 3 seed를 추가하거나, 제외 사유를 "같은 조건 재현 미완, 문헌값 0.748 참고"로 정직하게 적는다.

### COMMON-P1-01 · "제조 이상 확률" 요구를 충족하지 못한다 — `1−p`는 확률이 아니다

- **심각도**: P1 (문항 2 첫 문장이 직접 요구)
- **관련 문항·예상 감점**: 문항 2 (−3 ~ −6점), 문항 5 확률보정 (−1 ~ −2점)
- **개념 구분 (본 감사의 판정)**

  | 양 | 정의 | 본 데이터에서의 의미 | "이상 확률"로 부를 수 있나 |
  |---|---|---|---|
  | anomaly score | 모델 출력 (거리·경로길이 등) | 순위 정보만 있음 | 불가 |
  | conformal p-value | 정상 보정 점수 중 이 점수 이상인 비율 | 교환가능성이 성립하면 정상에서 균등분포 | 불가 (정상성 순위) |
  | `1 − p` | p의 단조변환 | 정상 window도 평균 0.5 | **불가** |
  | 보정확률 (Platt·isotonic) | 라벨로 점수 → P(y=1\|s) 학습 | 학습에 쓴 유병률·사건에 조건부 | 조건부로만 가능 |
  | 실제 고장발생 확률 | 현장 사전확률 × 우도비 | 독립 고장 사례와 현장 유병률 필요 | 이 데이터로 **식별 불가** |

- **실제 증거 (재계산)**

  | | Plan A `anomaly_prob` | Plan C `fault_risk` |
  |---|---|---|
  | 정의 | `1 − conformal_p` (`run_all.py:258`) | `1 − p_fault` (`pipeline.py:540`) |
  | 정상 window 중 > 0.5 | **65.5%** | **51.0%** |
  | 정상 window 중 > 0.9 | 23.0% | 9.4% |
  | 정상 window 중앙값 | 0.634 | 0.509 |
  | Brier score | **0.402** | **0.324** |
  | 상수(유병률) 예측의 Brier | 0.090 | 0.027 |
  | 보정 균등성 KS (정상) | 0.161 (n = 2,489, 임계 ≈ 0.027) | (window C0 FP율 평균 0.0045 / α 0.005) |

  - 두 Plan 모두 확률 출력이 **아무 정보 없이 유병률만 예측한 경우보다 Brier가 4.5–12배 나쁘다.**
  - Plan A: 미탐지 window 37개의 `anomaly_prob` 중앙값이 0.994인데 `alarm = 0`이다. 확률과 경보가 서로 다른 말을 한다.
  - Plan C는 README에 "conformal p-value는 정상성 순위이며 고장 사후확률이 아니다"(`plan_c_submission/README.md:41`)라고 정확히 적었지만 열 이름은 `fault_risk`다. Plan A는 열 이름 자체가 `anomaly_prob`다.
- **Calibration 평가의 타당성**: 라벨이 있는 **독립 검증셋이 없다.** 이상 라벨은 고장 1건뿐이므로, 보정기를 학습하면 같은 사건으로 평가하게 된다. 정상만으로 하는 보정(conformal)은 "오경보율 통제" 주장만 지지하고, 그것도 교환가능성이 깨지면(Plan A KS 0.161, Plan A 논문 "최대 84배 초과") 지지하지 못한다.
- **심사위원 질문**: "정상 window의 절반 이상이 이상 확률 0.5를 넘는데, 이것을 확률이라고 할 수 있습니까?"
- **최소 수정안**
  1. 열 이름을 `normality_p`, `risk_rank`로 바꾸고 "확률 아님"을 명시한다.
  2. "이상 확률" 열을 따로 만든다. 교차적합(정상 블록 × 이상 burst 그룹 leave-group-out)으로 Platt/isotonic 보정 → P(이상 | 점수, 본 데이터 유병률). 신뢰도 곡선과 Brier를 제시한다.
  3. 현장 사전확률 π(예: 1%)를 입력으로 받는 Bayes 변환 P = LR·π / (LR·π + 1 − π)을 제시한다. "π에 조건부인 이상 확률"이라고 명시하고, 고장 1건이라는 한계를 적는다.
- **수정 완료 판정 기준**: 예측파일의 확률 열이 보정곡선·Brier와 함께 보고되고, 그 Brier가 상수 예측보다 낮다.

```python
import numpy as np, pandas as pd, data as D, models as M, evaluate as E
ctx = D.build(); Fn, Tn, Fa = ctx['Fn'], ctx['Tn'], ctx['Fa']
folds = {'orig': (Tn<12000, (Tn>=12000)&(Tn<15000), Tn>=15000),
         'test0-5k': (Tn>=8000, (Tn>=5000)&(Tn<8000), Tn<5000),
         'test5-10k': ((Tn<4980)|(Tn>=13000), (Tn>=10000)&(Tn<13000), (Tn>=5000)&(Tn<9980)),
         'test10-15k': ((Tn<9980)|(Tn>=18000), (Tn>=15000)&(Tn<18000), (Tn>=10000)&(Tn<14980))}
rows = []
for fk, (mtr, mva, mte) in folds.items():
    for fs in ['S0_AMP4', 'S1_VIB', 'S2_SHAPE', 'S3_SPEC']:
        c = D.FEATURE_SETS[fs]
        for det in M.registry():
            Xtr, Xva, Xte, Xa = Fn[mtr][:, c], Fn[mva][:, c], Fn[mte][:, c], Fa[:, c]
            if det.needs_scaling:
                sc = M.Standardizer().fit(Xtr); Xtr, Xva, Xte, Xa = map(sc.transform, (Xtr, Xva, Xte, Xa))
            det.fit(Xtr); th = np.quantile(det.score(Xva), .999)
            w = E.window_metrics((det.score(Xte) > th).astype(int), (det.score(Xa) > th).astype(int))
            rows.append(dict(fold=fk, fs=fs, model=det.name, f1=w['f1'], FP=w['FP']))
r = pd.DataFrame(rows); r['rank'] = r.groupby('fold').f1.rank(ascending=False)
print(r[(r.fs == 'S1_VIB') & (r.model == 'BL0_Range')])
```
