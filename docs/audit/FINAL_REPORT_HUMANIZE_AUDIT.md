# 최종 결과보고서 문체 감사 — im-not-ai (Humanize KR) 플러그인 적용

대상: `plan_d_submission/report/결과보고서.md` (커밋 시점 A4 41쪽본)
작성일: 2026-10-06

**결론: AI 문체 위험은 '낮음'(플러그인 판정 risk_band low, 2점)이다.**
- 실증 6신호 중 3개가 발동했다.
  - 바로 적용할 수 있는 것: C-11 연결어미 뒤 쉼표 42건. 변경률 0.56%다.
  - 부분 적용: C-8 대구 1건, D-1 '따라서' 2~3건.
  - 적용하지 않음: E-1 장문화, E-2 종결 변주. 보고서 장르와 팀 작성 규약에 충돌한다.
- 이 감사는 문체만 본다. 내용·수치의 정확성은 `FINAL_REPORT_REREVIEW.md`가 다룬다.

---

## 1. 적용 범위와 방법

| 항목 | 내용 |
|---|---|
| 플러그인 | epoko77-ai/im-not-ai v2.3.2, 커밋 `2f3d943` (2026-09-26), MIT |
| 적용 단계 | ① 정량 사전점수 shim(`prepare_monolith_input.py`) ② 진단(`humanize-diagnostician`, standard 경로 1콜) ③ 실증 6신호 스캔(`/humanize-scan`, 걸린 문장을 실제로 고쳐 전후 계수) |
| 미적용 | 윤문 본 실행(monolith·finalizer). 보고서 원문은 수정하지 않았다 |
| 입력 A | 보고서 마크다운 전체 35,359자 (표·코드·참고문헌 포함) |
| 입력 B | 본문 산문 추출본 12,176자 (표·코드·그림·근거 줄·부록 제외, 196문장). 진단·스캔은 B로 수행 |
| 장르 지정 | `report` |
| 산출물 | `docs/audit/humanize_kr/`에 정량점수 2건, 진단서, 스캔 결과(바뀐 문장 52쌍 전부), 입력 B |

**해석상 제약 2가지**
1. 플러그인의 v2 기준선은 essay·news·blog·qa·dialogue 5종뿐이다. `report`를 주면 essay 기준선으로 대체된다(`metrics_v2.py` 802행).
2. 기준선 셀은 모두 `_placeholder: true, calibration_due: true`다. 따라서 z-점수(예: da_streak z=41)는 크기를 해석하지 않는다. 발동 여부만 쓴다.

- 판정: 발동 3개(C-8·E-1·C-11)라 스킬 규정상 "손볼 게 많습니다"다. 실질 강도가 큰 신호는 C-11 하나다.

## 4. 진단 — 문서를 지배하는 패턴 6개

| 순위 | ID [심각도] | 근거 (원문) | 플러그인 처방 | 팀 규약과의 관계 | 감사 판정 |
|---:|---|---|---|---|---|
| 1 | C-11 [S1] | "결측·시각 역행은 0건이지만, 관측 기간은…"(1.3 헤드). 헤드 메시지 약 30개가 "~이고/~지만, ~다" 한 틀 | 연결어미 직후 쉼표만 삭제. 헤드는 분할하지 않음 | 충돌 없음 | **적용** |
| 2 | E-2 | "[지표]은 [수치]다" 계사 종결 33문장 | 술어 변주(줄었다·그친다·넘는다) | 정도 부사·명사형 종결 금지와 부분 충돌 | **선택 적용**: 3.2·3.4·3.6의 연쇄에서만 수치를 받는 동사로 2~3곳 |
| 3 | A-13 [S2] | "교차검증 1단 섭동 오경보 한도를"(2.6 헤드) | 본문에서만 '의/에서' 1~2개 삽입 | 원인이 규약 4(지시어 금지 → 명사 반복). 헤드는 80자 제한 | **선택 적용**: 본문 4어 이상 명사구만 |

## 5. 적용하지 않는 처방과 근거

| 처방 | 근거 |
|---|---|
| E-1 장문화 (문장 잇기 12건) | 사람 기준 91.3/1,000문장은 편집된 칼럼·논설 코퍼스에서 나왔다. 이어 붙이면 수치·괄호가 3~4개 든 123~127자 문장이 생긴다(2.7, 5.4, 6.1). 규약 S9(120자 초과 경고)에 걸리고, 마침표가 갖던 주장 경계가 흐려진다 |
| E-2 종결 전면 변주 | 한다체 보고서는 모든 문장이 '-다'로 끝나 da_streak 25는 장르 고유값이다. 변주 수단(시제·서법 변경, 명사형 종결, 합쇼체 혼용)은 모두 금지 사항이거나 다른 AI 티다 |
| 헤드 메시지 제거·분할 (C-4·C-6 형태) | 팀 규약 6이 강제한다. 플러그인 진단도 보존 대상으로 분류했다 |
| 번호 목록의 산문화 (C-1·C-2) | 규약 7(줄글보다 표·목록). 플러그인도 리포트의 의미 있는 나열은 유지한다 |
| 괄호 속 수치·구간 정리 (J-4) | 실증상 괄호가 없는 쪽이 AI 신호다 |
| 영문 기술 용어 번역 (B-1·B-2) | 1.1 용어표에서 정의했다 |
| '~할 수 없다' 한계 진술 11회 변경 | A-10 서법 보존 대상이다 |
| H-1·G-3·A-17·I-1·A-2·D-4 | 플러그인 실증이 기각·보류한 패턴이다 |

## 6. 권고 수정 목록 (적용 시)

| 우선 | 내용 | 규모 | 위험 |
|---|---|---|---|
| 1 | C-11 연결어미 뒤 쉼표 삭제 (헤드 메시지 포함) | 42곳, 쉼표 1자씩 | 수치가 이어지는 문장(2.9 헤드 등)에서 절 경계를 찾기 조금 어려워짐 |
| 2 | D-1 '따라서' 5 → 2 (2.3·2.6 유지) | 3곳 | 없음 |
| 3 | C-8 1.5 "날짜만의 차이가 아니라" → "날짜 외에 계측 경로의 차이로도" | 1곳 | 없음 |
| 4 | E-2 3.2·3.4·3.6의 "~%다" 연쇄 중 2~3곳 동사 종결 | 2~3곳 | 정도 부사가 들어가면 S3 실패. 적용 후 `check_style.py` 재실행 필수 |
| 5 | A-13 본문 4어 이상 명사구에 조사 1개 | 선택 | 1.1 정의 용어를 쪼개면 용어 일관성이 깨짐 |

- 적용 후 `check_style.py`(작성 규약)와 `check_numbers.py`(수치 105건)를 다시 통과해야 한다.
- 원 계획상 수정은 우선 1~3만 권고한다. 변경률은 1% 미만으로 예상된다. 4~5는 문체 효과가 작고 규약 위반 위험이 있다.
