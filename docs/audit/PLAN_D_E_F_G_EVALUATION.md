- 종합점수는 5인 중 최고·최저를 버린 평균이다. 과장 표현 하나가 중간 3인 모두의 감점으로 이어지므로 금지 주장 정리(감사 §11)의 기대효과가 크다.

### 3.2 발표평가 우승 가능성

- D 본체안이 강점을 가지는 지점
  - 가이드북 LSTM-AE를 3 seed·800 epoch로 재현하고(0.743 vs 문헌 0.748), 같은 네트워크가 프로토콜만 바꾸면 0.959가 됨을 보인다. 이것은 "**평가 프로토콜이 성능 차이의 주원인**"이라는 강한 메시지다.
  - 섭동에 따른 오경보 증가를 정상 쪽에서 측정했다.
  - 2단 진동 확인으로 날짜·전류 교란을 방어한다.
- D 본체안이 약한 지점
  - 노랑 8.2%
  - 사후 게이트
  - 확률
- 판단: 위 세 약점을 발표 전에 **스스로 먼저 공개하고 대응안을 보여 주면** 우승권 경쟁이 가능하다. 공개하지 않은 상태에서 지적당하면 방어하기 어렵다.

## 4. 최종 선택: **5안 — Plan D를 본체로 하고, 다른 Plan의 검증·분석 방법만 D 결과에 다시 적용해 흡수**

### 4.1 선택 이유

| 안 | 판정 근거 |
|---|---|
| 1. D 단독 | 기본값으로 가장 좋다. 다만 문항 3(FN 공집합)과 문항 2(확률)의 결손을 F·E의 방법으로 메우면 2–3점이 더 오른다 → 5안 |
| 2. E 단독 | 최종 수치와 보정 확률은 가장 좋다. 그러나 주모델 gap 횡단, F 이후 개발(test 재사용), 운영안 부재, Linux 전용이 문제다. 출제 핵심(정상 운전변화 오경보·현장 활용)을 입증하는 구조가 약하다 |
| 3. F 단독 | 분석은 가장 정직하고 풍부하다. 그러나 최종모델 gap 횡단, 후처리 손실, 운영안 부재, 210 MB 패키지가 문제다 |
| 4. G 단독 | 예측결과 파일과 추론 경로가 없다(G-P0-01). 기간 내 불가 |
| **5. D 본체 + 흡수** | D만 공식 문항 4를 실제로 충족한다. 교란 방어 구조(2단), 가이드북 재현 기준선, OS 무관 1분 재현을 갖췄다. 결손은 **새 모델 없이** 분석 추가와 문서 정정으로 메울 수 있다 |
| 6. 모두 불가 | 4일 안에 D의 P0를 해소할 수 있으므로 해당하지 않는다 |

**선택 근거에 test 성능 비교를 쓰지 않았다.** E·F의 test는 같은 행을 두 번 본 상태다. D는 평가 단위가 달라 비교할 수 없다.

### 4.4 최종 평가 프로토콜

1. **모델 비교**: 5블록 CV(`e3_normal_block_cv.csv`, `e2_model_comparison.csv`), 단위 window, 유병률 약 12% 명시
2. **선정**: 개정 게이트(DL-001–003)를 쓰되, 원 게이트 결과(BL-0 선택)를 같은 표에 공개
3. **운영 성능**: `predictions.csv`의 holdout(블록 4) + fault만 사용
   - 빨강 기준: F1 0.931, Recall 0.876, FP 3 window
   - 1단 기준: F1 0.780, FPR 0.082
   - fit·calibration 행은 in-sample로 표시하고 성능에서 제외
4. **오경보율**: 블록별 경보 사건, Poisson 95% 상한(관측 0.105 h/블록), 최종 구성과 CV 구성의 차이(0.27% vs 8.2%)를 공개

6. **확률**: 교차적합 Platt(정상 OOF 블록 × fault burst 그룹 leave-group-out) → Brier, log-loss, 신뢰도 곡선. 임계값 불변. 사전확률 1/0.1/0.01% 사후확률 표(`posterior_sensitivity`)
