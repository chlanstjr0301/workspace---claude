# Plan D — 우승을 위한 실행계획

**과제 ③ · 진동·전류 시계열 기반 프레스 유압펌프 이상 조기탐지 및 오경보 분석**  
작성일 2026-10-04 · 제출 마감 2026-10-08 23:59

> 목표는 단순히 가장 높은 F1을 만드는 것이 아니다. 데이터가 허용하는 주장과 허용하지 않는 주장을 정확히 구분하고, **오경보에 강한 모델·실패 원인·현장 조치·완전 재현 코드**를 하나의 증거 사슬로 만들어 서면평가 상위 8팀과 최종 우승을 노린다.

## 0. 우승 전략 한 장 요약

### 프로젝트 한 문장

**CARE-Press: 수집 공백과 운전상태 변화를 고려하고, 경보 이유와 불확실성을 함께 제시하는 프레스 유압펌프 이상탐지 시스템**

- **C**ondition-aware: 정상 운전상태 변화와 저부하 구간을 별도로 다룬다.
- **A**cquisition-gap-aware: 5초 버스트 사이 공백을 가로지르는 가짜 window를 제거한다.
- **R**obust: 센서 이득·극성·오프셋 섭동에서도 성능이 유지되는지를 모델 선정 조건으로 둔다.
- **E**xplainable: 이상점수를 특징별·채널별 기여도로 분해하고 현장 점검 항목으로 연결한다.

### 심사위원에게 남길 세 문장

1. **이 데이터의 600개 이상 샘플은 600건의 고장이 아니라 서로 다른 날 수집된 고장 상태 1건의 조각이다.** 따라서 무작위 분할 F1을 부풀리지 않았다.
2. **정상 구간 안의 저부하 상태가 오경보의 주원인이며, 전류 시간구조가 탐지력의 주원인이다.** 둘을 분리해 검증하고 센서 조건 교란 가능성까지 시험했다.
3. **최종 출력은 단순 0/1이 아니라 정상성 p-value, 경보 단계, 원인 채널, 권장 조치다.** 평가 점수와 현장 의사결정을 연결했다.

### 우승을 위한 우선순위

| 순위 | 해야 할 일 | 이유 |
|---:|---|---|
| 1 | 동일 조건 모델 비교와 검증 누수 차단 | 40점 문항의 기반이며 모든 주장 신뢰도를 결정 |
| 2 | FP/FN 조건을 수치로 규명 | 15점 문항을 직접 충족하고 모델 선정근거가 됨 |
| 3 | 한 번에 재현되는 제출 코드 완성 | 확실히 확보할 수 있는 10점 |
| 4 | 경보→원인→조치의 현장 흐름 구현 | 산업 심사위원에게 가장 강한 차별점 |
| 5 | 보고서와 발표자료의 메시지 통일 | 정성평가 동점 우선 규칙에 유리 |
| 6 | 복잡한 딥러닝 추가 | 위 항목이 끝난 뒤에만 수행 |

## 2. 고정 분석 프로토콜

이 절은 결과를 보기 전에 동결한다. 이후 변경은 `decision_log.md`에 날짜·이유·영향을 기록한다.

### 2.1 데이터 단위

| 수준 | 정의 | 사용처 |
|---|---|---|
| Sample | 원본 1행, 약 0.1초 | 데이터 품질 점검만 |
| Window | 같은 버스트 안의 10샘플, stride 1 | 모델 입력과 정량 비교 |
| Burst | 시간 간격 0.5초 이하로 이어진 수집 묶음 | 오경보 병합, 탐지지연 민감도 |
| Fault record | 이상 CSV 전체 | 독립 양성 사건 수를 1로 해석 |

### 2.2 전처리

1. 원본 인덱스 열을 분리하고 `TimeStamp`를 시간형으로 변환한다.
2. 결측·중복·역행 타임스탬프를 검출하고 원본 행 번호를 보존한다.
3. 인접 시각 차이가 0.5초보다 크면 새 버스트로 나눈다.
4. window는 버스트 내부에서만 생성한다.
5. 기본 길이는 10샘플이며 5·20샘플을 민감도 분석한다.
6. 모든 스케일러와 특징 기준값은 해당 fold의 정상 학습구간에만 적합한다.
7. 이상 데이터는 임계값·특징 선택·하이퍼파라미터 선택에 사용하지 않는 것이 원칙이다.
8. 이미 수행된 이상 데이터 탐색의 선택 편향은 보고서 한계에 공개하고, Plan D 이후 설정을 동결한다.

### 2.3 정상 블록 교차검증

- 정상 20,000행을 시간순 5개 블록으로 나눈다.
- 매 fold에서 3블록은 학습, 1블록은 calibration, 1블록은 정상 holdout으로 사용한다.
- 모든 블록이 정확히 한 번 holdout이 되도록 순환한다.
- 인접 window가 fold 경계를 공유하지 않도록 경계 버스트 전체를 한쪽에 배정한다.
- 랜덤 K-fold와 window 단위 셔플은 금지한다.
- 모델·특징·임계값 선택은 정상 holdout 오경보와 섭동 강건성을 우선한다.

### 2.4 이상 데이터 사용 규칙

- 이상 CSV 전체는 최종 동결 모델에 한 번 평가하는 것이 이상적이다.
- 기존 사전실험에서 이미 반복 사용했으므로 이를 완전한 미지 테스트라고 주장하지 않는다.
- 모델 비교표에는 동일한 이상 window 집합을 사용한다.
- 신뢰구간의 독립 단위는 window 428개가 아니라 fault record 1건임을 각주로 단다.
- 통계적 우월성보다 **강건성·오경보·설명 가능성**으로 최종모델을 선정한다.

## 3. 특징 설계

### 3.1 기본 특징군

| 군 | 특징 | 목적 | 교란 민감도 |
|---|---|---|---|
| A 진폭 | 채널별 표준편차, peak-to-peak, RMS | 부하·진동 크기 | 센서 이득에 민감 |
| S 형태 | 채널별 lag-1·lag-2 자기상관, zero-crossing rate | 저주파 시간구조 | 이득·오프셋에 비교적 강건 |
| R 관계 | AI0–AI1 상관, 절댓값 상관, 표준편차 비 | 상·하부 센서 상호작용 | 극성/이득 변화에 따라 구분 |
| O 수준 | 전류 평균, 절댓값 평균 | 전류 부하 수준 | 오프셋·이득에 민감 |
| Q 품질 | window 시간간격 변동, 버스트 내 위치 | 수집 품질·초기구간 분석 | 고장 특징과 분리해 사용 |

### 3.2 운전상태 표현

- 정상 학습 데이터에서 `AI0_RMS`, `AI1_RMS`, `AI2_RMS`로 저·중·고 부하 상태를 만든다.
- 상태 경계는 학습 fold의 분위수로만 결정한다.
- 상태별 모델을 무조건 만드는 대신 다음 두 방법을 비교한다.
  1. 공통 모델 + 상태별 conformal calibration
  2. 공통 calibration + 상태 특징 추가
- 정상 holdout의 최악 블록 오경보가 감소할 때만 상태 적응 방식을 채택한다.
- holdout이 학습상태 범위를 벗어나면 고장으로 단정하지 않고 `unknown operating regime` 표시를 별도로 남긴다.

### 3.3 사용하지 않을 특징

- 결함주파수, envelope spectrum 등 5 Hz를 넘는 물리 주파수 해석
- 날짜, 파일명, 원본 행 번호처럼 라벨을 대리하는 값
- `Equipment_state`에서 파생된 모든 값
- 전체 데이터로 계산한 정규화 계수
- 이상 데이터에서 좋아 보였다는 이유만으로 추가한 단일 특징

## 4. 모델 포트폴리오

모든 모델은 동일 window, 동일 fold, 동일 정상 calibration 조건에서 비교한다.

| ID | 모델 | 역할 | 필수 여부 |
|---|---|---|---|
| BL-0 | 학습 정상 범위 이탈 규칙 | 설명 가능한 최저 기준선 | 필수 |
| BL-1 | 공식 LSTM-Autoencoder 재현 | 가이드북 기준선 | 필수 |
| M1 | Shrinkage Mahalanobis / Hotelling T² | 화이트박스 주력 후보 | 필수 |
| M2 | Isolation Forest | 비선형 트리 앙상블 비교 | 필수 |
| M3 | PCA-MSPC: T² + SPE/Q | 제조현장 표준·기여도 분석 | 필수 |
| M4 | 1D-CNN Autoencoder | 짧은 window용 딥러닝 대안 | 선택 |
| F | CARE-Press 결합판정 | 최종 운영 모델 | 필수 |

### 4.1 공식 LSTM-AE 재현 조건

- 가이드북 구조 `64-32-Repeat-32-64`를 그대로 재현한다.
- 가이드북 방식과 수정 방식 두 가지를 분리한다.
  - `G0`: abs, naive window, offset 100, 마지막 시점 MSE, 이상 포함 임계값
  - `G1`: 원신호, gap-aware, offset 0, 전체 window MSE, 정상 전용 임계값
- `G0`는 재현용일 뿐 최종 후보로 선정하지 않는다.
- 학습 예산과 EarlyStopping 실제 epoch를 기록한다.
- TensorFlow가 없는 환경에서도 나머지 모델과 보고서 산출은 실행되도록 선택 옵션으로 격리한다.

### 4.2 CARE-Press 최종 후보 구조

```text
원시 CSV
  → 데이터 품질 검사
  → 버스트 분할·gap-aware window
  → A/S/R/O 특징
  → 1단: 강건한 형태 기반 탐지기
  → 2단: 전류 독립 진동 증거 + 운전상태 확인
  → 정상성 conformal p-value와 특징 기여도
  → 초록 / 노랑 / 빨강 + 점검 권고
```

최종 결합은 복잡한 평균 앙상블이 아니라 **증거 역할이 다른 두 모델**로 구성한다.

| 1단 탐지 | 2단 확인 | 판정 | 의미 |
|---|---|---|---|
| 정상 | 무관 | 초록 | 현재 정상분포 안 |
| 이상 | 정상 또는 미지상태 | 노랑 | 계측 조건·새 운전상태·초기 이상 가능성 |
| 이상 | 진동도 이상 | 빨강 | 설비 이상 가능성이 높아 즉시 점검 |

1단과 2단의 구체 모델은 §6 통과 기준으로 결정한다. 사전실험상 1단은 형태 기반 마할라노비스, 2단은 전류 제외 진동 모델이 유력하지만 아직 확정하지 않는다.

## 5. 확률·불확실성 출력

### 5.1 정상성 conformal p-value

정상 calibration 점수 `s_1, ..., s_n`과 새 점수 `s(x)`에 대해:

```text
p_normal(x) = (1 + count(s_i >= s(x))) / (n + 1)
risk_score(x) = 1 - p_normal(x)
```

- `p_normal`은 정상 설비에서 이보다 극단적인 점수가 나올 빈도다.
- `risk_score`는 순위 기반 이상위험 점수이지 고장 사후확률이라고 단정하지 않는다.
- 현장 고장률을 1%, 0.1%, 0.01%로 가정한 사후확률 민감도 표를 별도로 제시한다.
- calibration curve는 이상 이벤트가 1건이라는 한계와 함께 제시한다.

### 5.2 경보 임계값

- 초기 후보: 노랑 `p_normal ≤ 0.01`
- 빨강: 1단과 2단 모두 `p_normal ≤ 0.01`
- 최종 값은 정상 블록 CV의 오경보 예산으로 결정한다.
- 오경보 0건도 `FAR=0`만 쓰지 않고 Poisson 95% 상한을 병기한다.
- 8시간 교대당 허용 알람 수를 기준으로 운영 임계값을 역산한다.

## 6. 평가와 모델 선정 규칙

### 6.1 필수 지표

| 축 | 지표 | 표기 규칙 |
|---|---|---|
| 탐지 | Window Recall, AP, AUROC | 동일 이상 window에서 비교 |

| 오경보 | 정상 블록별 FP window, 경보 이벤트, FAR/h | 평균뿐 아니라 최악 블록 표시 |
| 지연 | 버스트 진입점별 탐지지연 | 실제 고장 리드타임이 아님을 명시 |
| 강건성 | 극성·이득·오프셋·sampling jitter 후 Recall 변화 | 절대값과 하락폭 모두 표시 |
| 설명성 | 상위 기여 특징 안정성 | fold 간 순위 일치도 표시 |
| 효율 | 학습시간, 추론시간, 파라미터 수 | 현장 적용 근거 |

### 6.2 모델 통과 기준

아래 순서로 탈락시킨다.

1. 코드가 전체 fold에서 실패하거나 NaN을 내면 탈락.
2. 섭동 후 Recall이 원본 대비 20%p 이상 하락하면 주력 모델에서 탈락.
3. 정상 블록 CV에서 최악 블록 오경보가 BL-0보다 많으면 탈락.
4. 이상 fault record의 어느 버스트에서도 경보를 내지 못하면 탈락.
5. 남은 모델 중 최악 블록 FAR 상한이 낮은 모델을 우선한다.
6. 동률이면 Recall, 설명성, 추론비용 순으로 결정한다.

F1 최고 모델을 자동 선택하지 않는다. 단, 공지 요구를 충족하도록 F1은 모든 비교표에 반드시 포함한다.

### 6.3 반드시 수행할 실험

| ID | 실험 | 답할 질문 | 산출물 |
|---|---|---|---|
| E0 | 데이터 품질·버스트 진단 | 연속 시계열인가 | 수집 타임라인, run 표 |
| E1 | 5/10/20 window 민감도 | 길이에 따른 표본·성능 trade-off | 잔존율·성능 표 |
| E2 | 동일 조건 모델 벤치마크 | 무엇을 최종모델로 고를 것인가 | 핵심 성능표 |
| E3 | 정상 5블록 CV | 정상 운전변화에서 오경보가 나는가 | 블록 heatmap, FAR 상한 |
| E4 | 특징군 ablation A/S/R/O | 탐지력을 만드는 변수는 무엇인가 | ablation 표 |

### 6.4 중단 기준

- M4 1D-CNN-AE는 10월 6일 오전까지 M1/M3를 이기지 못하면 중단한다.
- 하이퍼파라미터 탐색은 모델당 최대 12개 조합으로 제한한다.
- 이상 데이터를 본 뒤 추가 탐색하지 않는다.
- 딥러닝이 블록 오경보·강건성·설명성 중 둘 이상을 개선하지 못하면 비교군으로만 둔다.

## 8. 오류분석 설계

### 8.1 FP 조건

다음 조건별로 정상 holdout의 FP window와 경보 이벤트를 집계한다.

- 저·중·고 부하
- 버스트 시작 1초 이내 / 이후
- 직전 window 대비 진폭 변화 상위 10%
- 정상 시간 블록 0~9
- 학습 상태 범위 안 / `unknown regime`
- 채널별 clipping·극값·시간간격 이상 여부

### 8.2 FN 조건

- 이상 수집 버스트별 탐지 여부
- 버스트 시작 1초 이내 / 이후
- 전류 증거 있음 / 진동 증거 있음 / 둘 다 있음
- 낮은 진폭이지만 형태가 이상한 window
- 1단만 탐지 / 2단만 탐지 / 둘 다 탐지

### 8.3 설명 가능성

- 마할라노비스 점수를 공분산 역행렬 기반 특징 기여로 분해한다.
- PCA-MSPC는 T²와 SPE 기여도 플롯을 제공한다.
- Isolation Forest는 permutation importance를 보조로 사용한다.
- LSTM-AE는 채널별·시점별 재구성 오차 heatmap을 사용한다.
- 서로 다른 설명법의 공통 상위 채널이 일치하는지 확인한다.
- 물리 원인은 “가능성”으로 쓰고 데이터로 특정할 수 없는 기어·베어링 고장을 단정하지 않는다.

## 11. 보고서 설계

### 내용요약 첫 문단 초안

> 제공 데이터는 10 Hz 연속 시계열이 아니라 최대 5초 길이의 버스트 수집이며, 정상과 이상이 서로 다른 날짜의 단일 기록으로 구성되어 있다. 본 연구는 이 구조를 무시할 때 발생하는 검증 누수와 오경보를 먼저 진단하고, 수집 공백을 고려한 windowing, 정상 시간블록 교차검증, 센서 조건 섭동시험을 결합한 CARE-Press를 제안한다. 최종 시스템은 정상성 p-value와 원인 기여도를 이용해 초록·노랑·빨강 경보와 점검 순서를 함께 제공한다.

### 장별 헤드 메시지와 필수 그림

| 장 | 헤드 메시지 | 필수 표·그림 |
|---|---|---|
| 1 | 데이터는 연속 시계열이 아니라 버스트이며 독립 고장은 1건이다 | 수집 타임라인, 버스트 길이, 저부하 블록 |
| 2 | 같은 조건에서 비교했을 때 최종모델은 최고 F1보다 오경보·강건성이 우수했다 | 모델 종합표, ROC/PR, 블록별 오경보 |
| 3 | 전류 형태가 탐지를, 미학습 저부하가 오경보를 좌우했다 | ablation, FP/FN heatmap, 기여도 |
| 4 | 경보는 원인과 다음 조치까지 제공해야 현장에서 쓰인다 | 3단 신호등, 점검 의사결정 흐름 |
| 5 | 차별점은 복잡한 모델이 아니라 데이터 한계를 검증체계로 바꾼 것이다 | 기존 방식 vs CARE-Press 비교 |
| 6 | 평가자가 한 명령으로 모든 결과를 재생성할 수 있다 | 코드 구조, 실행 로그, 산출물 목록 |

### 보고서에서 반드시 각주로 밝힐 것

- 정상/이상 수집일이 다름
- 이상 fault record가 1건임
- window가 서로 중첩되어 독립 표본이 아님
- 이상 시작 이전 데이터가 없어 진짜 리드타임은 측정 불가
- conformal 보장은 정상 데이터의 교환가능성에 의존함
- 0건 오경보는 장기 FAR=0의 증거가 아님
- Plan D 이전 사전실험에서 이상 데이터를 이미 관찰했음

## 12. 발표자료 설계

발표자료는 12장으로 제한한다.

1. 문제와 한 줄 해결책
2. 공식 방법을 그대로 믿을 수 없었던 이유 3가지
3. 버스트 수집과 날짜 교란
4. 평가 프로토콜과 누수 차단
5. CARE-Press 구조
6. 동일 조건 모델 비교
7. 왜 최고 F1 모델을 고르지 않았는가
8. 영향변수와 상호작용
9. 오경보가 발생하는 조건
10. 초록·노랑·빨강 현장 운영
11. 재현성과 추가 데이터 계획
12. 결론: 정직한 검증이 현장 신뢰를 만든다

발표에서 먼저 답할 예상 질문:

- 왜 LSTM이 최종모델이 아닌가?
- 전류 자기상관이 날짜 차이일 가능성은?
- 이상 이벤트 1건으로 일반화가 가능한가?
- 오경보 0건을 어떻게 믿는가?
- 이 모델을 현장에 설치하면 작업자는 무엇을 하는가?
- 왜 FFT나 Transformer를 사용하지 않았는가?

## 14. 하지 않을 것

- 이상 window를 무작위로 train/test에 섞지 않는다.
- 이상 데이터로 운영 임계값을 최적화하지 않는다.
- Accuracy 97% 같은 불균형 착시를 전면에 내세우지 않는다.
- 21개 버스트를 21건의 고장이라고 부르지 않는다.
- 탐지지연을 고장 전 리드타임이라고 부르지 않는다.
- 10 Hz 데이터에서 기어 맞물림 주파수를 해석하지 않는다.
- 근거 없이 SMOTE, Transformer, 대규모 하이퍼파라미터 탐색을 추가하지 않는다.
- 전류 한 특징이 완전 분리된다고 해서 원인을 고장으로 확정하지 않는다.
- 외부데이터를 장식용으로 넣지 않는다.
- 마지막 날까지 모델을 바꾸지 않는다.

## 16. 최종 성공 정의

Plan D의 성공은 F1 하나가 가장 높은 상태가 아니다. 다음 다섯 가지가 동시에 성립해야 한다.

1. 데이터 구조와 한계를 심사위원보다 먼저 설명한다.
2. 비교 모델이 동일 조건에서 재현되고 선정 규칙이 사전에 고정된다.
3. 오경보와 미탐지 조건을 수치와 원인으로 제시한다.
4. 모델 출력이 구체적인 현장 조치로 이어진다.
5. 평가자가 한 명령으로 모든 핵심 결과를 다시 만든다.

이 다섯 항목을 완성하면 이 프로젝트의 경쟁력은 “모델 하나”가 아니라 **신뢰할 수 있는 제조 AI 분석 전체 과정**이 된다.
