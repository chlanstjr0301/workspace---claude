# 성과 지표 정의서 (Model Performance Indicators)

**과제 ③ — 진동·전류 시계열 기반 프레스 유압펌프 이상 조기탐지 및 오경보 분석**
Plan A / 작성 2026-10-03

> 이 문서는 "무엇을 숫자로 주장할 것인가"를 고정하는 문서다. 모델을 바꿔도 이 지표 세트는 바꾸지 않는다.
> 인용된 모든 수치는 같은 폴더의 `baseline_check.py`로 재현 가능하다.

## 0. 한 장 요약

| 층위 | 지표 | 역할 | 목표 |
|---|---|---|---|
| **1차** | **Event Recall** (이벤트 단위 탐지율) | 고장을 놓쳤는가 | 1.00 |
| **1차** | **FAR/h** (시간당 오경보 건수) | 현장이 알람을 믿는가 | ≤ 1건/h |
| **1차** | **Detection Lead Time** (조기탐지 리드타임) | "조기"탐지가 맞는가 | ≥ 10 s |
| 2차 | Window F1 / PR-AUC(AP) | 대회 명시 지표·모델 간 비교 | 베이스라인 초과 |
| 2차 | Recall @ FPR ≤ 0.1 % | 임계값 공정 비교 | 최대화 |
| 2차 | MCC | 불균형 보정 요약 | 보조 |
| 진단 | 조건별 FN/FP 분해표 | 문항 3 (15점) 근거 | 필수 |

**핵심 결론 3줄**

1. Window F1 단독으로는 변별력이 없다 — **학습 없는 1줄 규칙이 가이드북 LSTM-AE(F1 0.748)를 이긴다**(동일 조건 F1 0.857, gap-aware 보정 후 **0.818**). (§2, §7.1)
2. 따라서 1차 지표를 **이벤트 단위 + 시간당 오경보 + 리드타임**으로 올린다. 대회가 명시한 F1은 "제출용 2차 지표"로 내린다. (§4)
3. 양성 이벤트가 **단 1건**이므로 모든 window 단위 신뢰구간은 과소추정된다. 구간 부트스트랩으로만 불확실성을 말한다. (§11)

## 1. 지표 설계 전에 확인한 데이터 사실

`data/raw/` 실측

| 항목 | press_data_normal.csv | press_data_outlier.csv |
|---|---|---|
| 행 수 | 20,000 | 600 |
| 기간 | 2022-07-12 00:00:00 ~ 01:16:55 (4,616 s) | 2022-07-17 10:51:07 ~ 10:53:53 (166 s) |
| `Equipment_state` | 전 행 `0` | 전 행 `1` |
| 샘플링 | 0.1 s (10 Hz) 중앙값 | 0.1 s (10 Hz) |
| 0.5 s 초과 결측구간 | 598개 (중앙 4.2 s, 최대 16.6 s) | 20개 (중앙 5.4 s, 최대 8.6 s) |
| **연속 구간(burst) 수** | **599개** (평균 33.4샘플, **최대 50**) | **21개** (평균 28.6샘플, 최대 50) |
| **공백이 차지하는 시간 비율** | 4,616 s 중 2,676 s = **58.0 %** | 166 s 중 108 s = **65.0 %** |
| 실측 데이터 시간 (행수×0.1 s) | 2,000 s | 60 s |
| 결측치 | 없음 | 없음 |
| 중복 타임스탬프 | 1건 | 0건 |

지표 설계에 직접 영향을 주는 5가지:

1. **라벨은 행 단위가 아니라 파일 단위다.** `Equipment_state`는 파일 내에서 상수다. → "이상 구간의 시작 시점"이라는 정답이 존재하지 않는다. 리드타임은 *정의해서 만들어 써야 하는* 지표다. (§4.3)
2. **양성 이벤트 수 = 1.** 480개 window는 전부 같은 2.8분 기록에서 나온 것이다. 독립 표본 수는 480이 아니라 **1**이다. → window 단위 F1의 ±신뢰구간은 전부 거짓말이다.
3. **날짜 교란(confound).** 정상은 7/12, 이상은 7/17. 모델이 "고장"이 아니라 "다른 날"을 학습해도 점수가 나온다. → 날짜 교란 통제 실험이 필수다. (§6.3)
4. **이 데이터는 연속 시계열이 아니라 버스트 샘플링이다.** (§1.1) 10 Hz로 최대 50샘플(5 s)을 받고 쉬는 패턴이 반복되며, 벽시계 시간의 **58 %가 공백**이다. 20샘플 window를 순진하게 만들면 **절반이 공백을 가로지른다**. → gap-aware windowing은 전처리 취향이 아니라 **지표 타당성 문제**다.
5. **클래스 비율이 인위적이다.** 테스트 유병률 180/4,180 = 4.3%는 두 파일의 크기 비율일 뿐 현장 실제 고장률이 아니다. → **Precision·F1·Accuracy는 유병률 의존 지표**이므로 단독 주장 금지. 유병률 무관 지표(Recall, FPR, FAR/h)를 반드시 병기한다. (§4.4)

### 1.1 버스트 샘플링 구조 (gap-aware windowing의 근거)

`gap_aware_check.py --runs` 측정값.

| 항목 | normal | outlier |
|---|---|---|
| 연속 구간(run) 수 | 599 | 21 |
| run 길이 (샘플) | min 1 / 중앙 37 / **max 50** | min 3 / 중앙 28 / **max 50** |
| run 길이가 정확히 50인 비율 | 33.7 % | 23.8 % |
| 공백 총합 / 전체 기간 | **58.0 %** | **65.0 %** |

**run 길이 상한이 두 파일 모두 정확히 50샘플(5 s)** 이라는 것은 DAQ가 "5초 수집 → 대기" 를 반복하는 **버스트 수집**이라는 뜻이다. 우연한 결측이 아니라 설계된 수집 주기다.

window 생성 시 살아남는 비율:

| window 길이 | gap-free window | naive stride-1 | 잔존율 | 길이 ≥ w 인 run |
|---|---|---|---|---|
| 20샘플 (2 s) | 9,978 | 19,981 | **49.9 %** | 452 / 599 |
| 10샘플 (1 s) | 14,871 | 19,991 | 74.4 % | 530 / 599 |
| 5샘플 (0.5 s) | 17,652 | 19,996 | 88.3 % | 570 / 599 |

**파생되는 2가지 수정 사항**

- **가이드북의 시간 환산이 틀렸다.** "과거 20개(2초)로 100시점(10초) 이후를 탐지"라고 쓰여 있으나, 공백 때문에 실제 벽시계 시간은 — 20샘플 window = **중앙값 3.6 s (최대 24.9 s)**, 100샘플 offset = **중앙값 21.7 s (범위 13.2~47.4 s)** 다. 즉 "10초 선행 예측"이 아니라 **평균 22초 선행**이며, 그나마 window마다 길이가 들쭉날쭉하다. gap-aware로 자르면 20샘플 window는 정확히 1.9 s로 고정된다.
- **window 길이 선택은 통계 효율 trade-off다.** 20샘플을 고수하면 표본의 절반을 버리고 run 599개 중 147개는 아예 window를 못 만든다. 10샘플로 줄이면 잔존율이 74 %로 올라간다. → window 길이를 **하이퍼파라미터로 탐색**하되, 각 길이에서 **잔존율을 반드시 함께 보고**한다.

## 2. Window F1을 1차 지표로 쓰면 안 되는 이유 (증거)

가이드북과 **완전히 동일한 분할**(train=normal[:15000], seq=20, offset=100, valid=정상 880 + 이상 300, test=정상 4,000 + 이상 180)에서 측정:

| 방법 | TP | FN | FP | TN | Precision | Recall | **F1** | FPR |
|---|---|---|---|---|---|---|---|---|
| 가이드북 LSTM-Autoencoder | 154 | 26 | 78 | 3,922 | 0.664 | 0.856 | **0.748** | 1.95 % |
| **학습 없는 1줄 규칙**: window 내 한 채널이라도 학습구간 min/max 밖 | 135 | 45 | **0** | 4,000 | **1.000** | 0.750 | **0.857** | **0.00 %** |
| AI0 window 표준편차 > 학습 q99.5 | 127 | 53 | 0 | 4,000 | 1.000 | 0.706 | 0.827 | 0.00 % |

원인은 분명하다. 이상 데이터는 학습구간 값 범위를 그냥 벗어난다:

| 채널 | 학습구간 범위 | 정상 테스트 이탈률 | 이상 이탈률 |
|---|---|---|---|
| AI0_Vibration | [-0.315, 0.352] | 0.000 % | **27.7 %** |
| AI1_Vibration | [-0.367, 0.400] | 0.000 % | **10.2 %** |
| AI2_Current | [-271.6, 273.2] | 0.000 % | **9.5 %** |
| 어느 한 채널이라도 (window 20, 가이드북 window 집합) | — | **0.000 %** | **70.4 %** |

**이것이 의미하는 바**

- 이 분할에서 window F1은 **0.85 근방에서 포화**된다. 딥러닝 모델이 0.80을 기록하면 "잘 됐다"가 아니라 **1줄 규칙보다 못한 것**이다.
- 따라서 보고서에 F1만 들고 가면, 심사위원 중 "학"이 이 계산을 1분 만에 재현하고 끝난다.
- **대응**: 이 trivial 규칙을 *우리가 먼저* 제시하고 "F1은 포화 지표"임을 증명한 뒤, 변별력 있는 1차 지표로 넘어간다. → 이것 자체가 문항 1(데이터 진단)·문항 3(오류분석)·문항 5(차별성) 득점 포인트다.

> **베이스라인 정책**: `BL-0 = 이 1줄 규칙`. 베이스라인은 Logistic Regression이 아니라 **BL-0**이다. 어떤 모델도 BL-0을 못 넘으면 보고서에 "최종모델"로 쓸 수 없다.

> **gap-aware 보정 후**: 위 표는 가이드북과 동일 조건(naive windowing)이라 비교용으로만 유효하다. 공백을 가로지르는 window를 제거하면 **BL-0 F1 = 0.818** (Precision 1.000 / Recall 0.692 / FPR 0.00 %)로 내려간다. 떨어진 몫이 전부 Recall인 것이 핵심 — 자세한 ablation은 §7.1. **합격선은 0.818을 쓴다.**

## 3. 평가 단위: 3층 구조

모든 지표는 **어느 층에서 측정했는지**를 반드시 명시한다. 층을 섞어 비교하는 순간 숫자가 무의미해진다.

| 층 | 정의 | 단위 수 | 쓰는 곳 |
|---|---|---|---|
| **L1 샘플** | 1행 = 0.1 s | 20,600 | 디버깅 전용. 보고서에 쓰지 않음 |
| **L2 윈도우** | 20샘플(1.9 s), stride 1, **gap-aware** | 정상 **2,489** / 이상 **276** (naive 4,880 / 480) | 대회 제출 F1, 모델 간 비교 |
| L2.5 버스트 | 연속 수집 구간 1개 (≤50샘플 = 5 s) | 정상 113 / 이상 13 | L3 병합의 자연 단위 |
| **L3 이벤트** | 연속 알람 구간을 1건으로 병합 | 양성 **1건** | **1차 지표**, 현장 해석 |

**L2 주의**: stride 1 window는 인접 window가 19/20 샘플을 공유한다. 독립 표본이 아니다.
→ (a) 유효 표본 수 ≈ 전체/20, (b) 부트스트랩은 반드시 **블록 단위**로.

**L3 병합 규칙** (고정):

```
알람 발생  : 연속 k개 window가 임계값 초과   (k = 5, 즉 0.5 s 디바운스)
알람 종료  : 연속 k개 window가 임계값 이하
이벤트 매칭: 알람 구간이 실제 이상 구간과 1샘플이라도 겹치면 TP 이벤트
            겹치지 않으면 FP 이벤트(= 오경보 1건)
```

`k`는 하이퍼파라미터가 아니라 **공정 상수로 선언**하고 민감도만 부록에 싣는다 (k = 1, 3, 5, 10).

## 4. 지표 정의

### 4.1 1차 지표 (보고서 본문 / 발표 첫 장)

| # | 지표 | 정의 | 층 | 목표 | 근거 |
|---|---|---|---|---|---|
| P1 | **Event Recall** | 탐지한 이상 이벤트 / 전체 이상 이벤트 | L3 | 1.00 | "이상을 많이 탐지" (출제문) |
| P2 | **FAR/h** (False Alarm Rate) | FP 이벤트 수 ÷ 정상 관측시간(h) | L3 | **≤ 1 건/h** | "오경보를 줄이고" (출제문) |
| P3 | **Detection Lead Time** | 이상 구간 시작 − 최초 알람 시각 | L3 | ≥ 10 s | "조기에 탐지" (출제문) |

> **P2가 왜 FPR이 아니라 FAR/h인가**: 가이드북 모델의 FPR 1.95%는 수치만 보면 양호하다. 그러나 10 Hz · stride 1에서 FP window 78개는 400초(6.7분) 구간에 몰려 있다 → **환산하면 시간당 약 700회의 알람**이다. 작업자는 첫날 알람을 꺼버린다. FPR은 현장 언어가 아니고 FAR/h는 현장 언어다. 평가자 중 "산"이 보는 지표가 이것이다.

### 4.2 2차 지표 (대회 명시 지표 + 모델 비교)

| # | 지표 | 정의 | 비고 |
|---|---|---|---|
| S1 | **F1** | 2PR/(P+R) | 문항 2 원문은 **"(F1-score 등)"** — 지정 지표가 아니라 **예시**다. 따라서 1차 지표를 이벤트 단위로 올려도 규정 위반이 아니다. 다만 배점표에 이름이 적힌 **유일한** 지표이므로 **반드시 병기**하고, 측정 층(L2)을 명시한다 |
| S2 | **PR-AUC (AP)** | Precision-Recall 곡선 아래 면적 | 임계값 무관 비교. 불균형에서 ROC-AUC보다 정직 |
| S3 | **Recall @ FPR ≤ 0.1 %** | FPR 상한 고정 시 달성 Recall | 모델 간 **공정 비교의 핵심**. 임계값 튜닝 유불리 제거 |
| S4 | **MCC** | 혼동행렬 4칸을 모두 쓰는 상관계수 | 불균형에서 Accuracy·F1보다 덜 속는다 |
| — | ~~Accuracy~~ | — | **보고서에서 제외.** 유병률 4.3%에서 전부 정상이라 찍어도 95.7% |

### 4.3 리드타임 지표를 "만들어 쓰는" 방법

`Equipment_state`에 이상 시작 시각이 없으므로 다음 중 하나를 **사전에 선언**하고 일관 적용한다.

| 방식 | 정의 | 장점 / 단점 |
|---|---|---|
| **A (채택)** | 이상 파일 **첫 행(10:51:07.943)을 이벤트 시작 t₀**으로 간주, 알람 시각과의 차 | 단순·재현 가능 / t₀가 실제 발단 시점이란 보장 없음 |
| B | 역방향 변화점 탐지(CUSUM/BOCPD)로 추정한 t₀ | 물리적으로 그럴듯 / 추정 불확실성이 지표에 전파 |
| C | 이상 파일을 전반/후반으로 나눠 전반부 탐지율로 대체 | 가정 최소 / "리드타임"이라 부를 수 없음 |

**A를 1차, B를 민감도 분석**으로 쓴다. 보고서에 "t₀는 관측 시작 시점이며 실제 고장 발단 시점의 하한"이라고 **명시**한다. 이 한 줄이 없으면 과대주장이 된다.

### 4.4 유병률 의존성 — 반드시 병기할 것

| 유병률 무관 | 유병률 의존 |
|---|---|
| Recall(TPR), FPR, Specificity, FAR/h, ROC-AUC | **Precision, F1, Accuracy, PR-AUC** |

보고서 표에는 항상 `(테스트 유병률 = 4.3 %, 현장 추정 유병률 = X %)`를 각주로 단다.
현장 유병률 가정을 바꿨을 때 Precision이 어떻게 붕괴하는지 1개 표로 보여준다 → 문항 4(현장 활용) 득점.

```
Precision(π) = TPR·π / (TPR·π + FPR·(1−π))
```

| 가정 유병률 π | TPR 0.75, FPR 0.1 % 일 때 Precision |
|---|---|
| 4.3 % (테스트) | 0.971 |
| 1 % | 0.883 |
| 0.1 % | 0.429 |
| 0.01 % | 0.070 |

→ **"FPR 0.1%면 충분"이 아니라는 것**을 이 표 하나로 증명할 수 있다. 차별성 득점 포인트.

## 5. 임계값 결정 규칙

가이드북은 **Precision = Recall 교점**을 임계값으로 썼다(≈0.0035). 이 방식의 문제:

- 교점은 **수학적 우연**이지 공정 비용과 무관하다.
- 그 결과가 FPR 1.95% = 수백 알람/h 였다. 즉 **교점 규칙이 오경보 요구사항을 정면으로 위반**한다.

**대체 규칙 (3개 모두 보고하고 1개를 최종 채택)**

| 규칙 | 정의 | 용도 |
|---|---|---|
| **T1 (채택)** | **FAR/h ≤ 1을 만족하는 최소 임계값** | 운영 임계값. 현장 제약이 먼저 |
| T2 | 정상 검증구간 재구성오차의 **q99.9 분위수** | 이상 데이터를 전혀 쓰지 않음 → 누수 없음 |
| T3 | 비용 최소화: `argmin (C_FN·FN + C_FP·FP)` | 비용 가정을 노출시켜 토론 가능하게 만듦 |

> **T2가 중요한 이유**: 가이드북은 임계값을 **이상 데이터 300개가 섞인 검증셋**에서 정했다. 이상 이벤트가 1건뿐이므로 이는 "테스트에 쓸 바로 그 이벤트로 임계값을 맞춘 것"이다 → **사실상 누수**. T2는 정상 데이터만으로 임계값을 정하므로 이 비판에서 자유롭다. 두 방식의 성능 차이를 보여주는 것 자체가 문항 3·5 득점이다.

**T3 비용 가정 템플릿** (보고서에 가정으로 명시, 숫자는 조사 후 채움)

| 항목 | 기호 | 가정값 | 출처 |
|---|---|---|---|
| 미탐지 1건 비용 (비가동 + 불량) | C_FN | ? 원 | 조사 필요 |
| 오경보 1건 비용 (점검 공수) | C_FP | ? 원 | 조사 필요 |
| 비용비 | C_FN / C_FP | **50 : 1 (초기 가정)** | 민감도 10~200 제시 |

## 6. 검증 프로토콜 (누수 차단)

### 6.1 분할 규칙

```
학습   : normal[:12000]            (정상만)
검증   : normal[12000:15000]       (정상만) ← 임계값 T2 결정
테스트 : normal[15000:] + outlier 전체
```

가이드북(train 15000 / valid에 이상 포함)과 달리 **검증에 이상 데이터를 넣지 않는다**. 유일한 이상 이벤트를 테스트에만 남겨둔다.

### 6.2 금지 사항 체크리스트

- [ ] 스케일러를 전체 데이터에 `fit` → **금지** (학습 구간만 `fit`)
- [ ] window 생성 후 셔플 분할 → **금지** (stride 1 중첩으로 train/test가 19/20 샘플 공유 = 심각한 누수)
- [ ] 이상 데이터로 임계값 튜닝 → **지양** (T2 사용, T1은 FAR 제약만 사용)
- [ ] window가 0.5 s 초과 결측구간을 가로지름 → **제거** (gap-aware windowing)
- [ ] 테스트 성능 보고 뒤 하이퍼파라미터 수정 → 수정했다면 **그 사실을 보고서에 기록**

### 6.3 날짜 교란 통제 실험 (차별성 핵심)

양성 데이터가 전부 다른 날(7/17)이므로, **"고장 탐지"가 아니라 "날짜 탐지"일 가능성**을 반드시 반증해야 한다.

| 실험 | 방법 | 통과 기준 |
|---|---|---|
| E1 | 정상 데이터를 7/12 내부에서 전/후반 분할 → 서로를 이상으로 탐지하는지 | FAR/h ≤ 1 (시간 흐름만으로는 알람이 안 떠야 함) |
| E2 | 채널별 ablation (AI0만 / AI1만 / AI2만 / 전체) | 특정 채널 단독으로도 탐지되면 그 채널의 물리적 근거 제시 |
| E3 | DC offset·gain 섭동 주입 후 재평가 | 센서 캘리브레이션 차이만으로 탐지되면 **실패**로 간주 |

E3에서 실패하면 그 모델은 "날짜 분류기"다. **이 실험을 하고 결과를 솔직히 쓰는 것**이 문항 3 만점 전략이다.

## 7. 베이스라인 보드 (넘어야 할 숫자)

### 7.1 windowing 선택이 BL-0에 미치는 영향 (ablation)

`gap_aware_check.py --ablation`. BL-0 = 학습 없는 범위 이탈 1줄 규칙.

| 케이스 | windowing | offset | 정상/이상 window | TP | FN | FP | Precision | Recall | **F1** | FPR |
|---|---|---|---|---|---|---|---|---|---|---|
| A | naive | 100 | 4,000 / 180 | 135 | 45 | 0 | 1.000 | 0.750 | **0.857** | 0.00 % |
| B | naive, valid 예약 없음 | 100 | 4,880 / 480 | 338 | 142 | 0 | 1.000 | 0.704 | 0.826 | 0.00 % |
| C | **gap-aware** | 100 | 2,433 / 239 | 155 | 84 | 0 | 1.000 | 0.649 | 0.787 | 0.00 % |
| **D** | **gap-aware** | 0 | **2,489 / 276** | 191 | 85 | 0 | **1.000** | **0.692** | **0.818** | **0.00 %** |
| E | gap-aware, 프로토콜 §6.1 | 0 | 2,489 / 276 | 191 | 85 | 0 | 1.000 | 0.692 | 0.818 | 0.00 % |

**읽는 법**

- **표본의 절반이 사라진다.** 정상 4,880 → 2,489, 이상 480 → 276. 기존 보고치는 **공백을 가로지르는 가짜 window를 절반 섞어 센 숫자**였다.
- **BL-0 F1 = 0.857 → 0.818** 로 내려간다. Precision 1.000 / FPR 0.00 %는 그대로다. 즉 떨어진 것은 전부 Recall(0.750 → 0.692)이며, **공백을 가로지르던 window가 인위적으로 큰 진폭 점프를 만들어 탐지를 쉽게 해주고 있었다**는 뜻이다. 가짜 신호였다.
- **D와 E가 동일한 이유**: BL-0의 임계값은 학습구간 min/max인데, `[:12000]`과 `[:15000]`의 경계 차이(AI1만 소폭)가 테스트 window 판정을 하나도 바꾸지 못했다. 구조적 동치가 아니라 이 규칙 한정의 우연이므로, 학습 기반 모델에서는 D·E를 따로 측정해야 한다.
- **가이드북 분할은 gap-aware와 양립 불가**: 이상 window를 300개 valid로 예약하는데, gap-aware로는 이상 window가 276개뿐이라 테스트에 남는 게 없다. §6.1 프로토콜(검증에 이상 미사용)로 가야만 하는 **구조적 이유**가 하나 더 생겼다.

### 7.3 burst 단위 결과 (L3 대용)

`gap_aware_check.py --burst`. 연속 구간(burst) 1개를 관측 1건으로 보고, burst 내 window가 하나라도 걸리면 이상으로 판정.

| 지표 | 값 |
|---|---|
| 정상 테스트 burst / 이상 burst | 113개 / 13개 |
| TP / FN / FP | 12 / 1 / **0** |
| Precision / Recall / F1 | 1.000 / **0.923** / **0.960** |
| **FAR/h** | **0.00 건/h** (정상 테스트 실측 0.139 h) |

> **해석 주의.** burst 단위로 올리면 숫자가 좋아 보이지만(F1 0.960), 이상 burst 13개는 **같은 1건의 고장 기록을 쪼갠 것**이므로 독립 표본이 아니다. 실질 이벤트 수는 여전히 **1**이다. 이 수치는 "§3 L3 병합 규칙의 상한 추정치"로만 쓰고, 보고서 본문에서 성능 주장으로 쓰지 않는다.
> 또한 정상 테스트 구간이 **0.139 h(500초)** 뿐이라 FAR/h = 0은 "오경보가 없다"가 아니라 **"8분 관측에서 못 봤다"** 이다. FAR/h를 주장하려면 정상 데이터 전체(2,000 s = 0.56 h)로 재측정해야 하며, 그래도 "시간당 1건"을 통계적으로 뒷받침하기엔 관측시간이 부족하다. → **FAR/h는 신뢰구간(Poisson upper bound)과 함께 보고한다.**

**합격선**: `F1 > 0.818` (gap-aware 기준) **그리고** `FAR/h ≤ 1` **그리고** `Event Recall = 1.0`. 셋 중 하나라도 미달이면 최종모델 후보에서 제외.

## 8. 오류분석 지표 (문항 3 — 15점)

출제문이 요구하는 것은 평균 성능이 아니라 **"미탐지·오경보가 집중되는 조건"**이다. 다음 분해표를 고정 양식으로 만든다.

### 8.1 조건 축 정의 (라벨이 없으므로 신호에서 파생)

| 조건 축 | 파생 방법 | 왜 |
|---|---|---|
| 부하 수준 | `AI2_Current` window RMS를 3분위 (저/중/고) | 가동/비가동 구분 대리변수 |
| 진동 에너지 | `AI0/AI1` window RMS 3분위 | 운전 강도 |
| 전환 구간 | window 내 RMS 변화율 상위 10% | "정상적인 운전변화" = 오경보 주범 후보 |
| 결측 인접 | 0.5 s 초과 공백에서 ±2 s 이내 | 데이터 품질 유래 오경보 |
| 시간대 | 타임스탬프 10분 bin | 드리프트 |

### 8.2 분해표 양식

| 조건 | window 수 | TP | FN | FP | Recall | FAR/h | 해석 |
|---|---|---|---|---|---|---|---|
| 부하 저 | | | | | | | |
| 부하 중 | | | | | | | |
| 부하 고 | | | | | | | |
| 전환 구간 | | | | | | | |
| 결측 인접 | | | | | | | |

**주장 문장 템플릿** (보고서에 그대로 쓸 형태):
> "FN은 **부하 저 구간**에 N건 중 M건(x %)이 집중되었다. 이는 유압펌프 부하가 낮을 때 진동 진폭 자체가 작아 이상 패턴이 정상 분산 내에 묻히기 때문이며, 해당 구간에서는 임계값을 θ_low로 낮춘 조건부 임계값을 적용해 Recall을 r₁ → r₂로 개선하였다."

이렇게 **조건 → 물리적 이유 → 조치 → 개선 수치**까지 묶어야 15점이 나온다. 조건만 나열하면 절반이다.

## 9. 현장 활용 지표 (문항 4 — 10점)

모델 출력을 그대로 두지 않고 **작업자 행동**으로 변환하는 지표.

| 지표 | 정의 | 목표 |
|---|---|---|
| 점검 우선순위 Precision@k | 알람 상위 k건 중 실제 이상 비율 | k=5에서 ≥ 0.8 |
| 조치 가능 리드타임 | P3에서 알람 전파·확인 지연(가정 30 s) 차감 | > 0 |
| 알람 피로도 | 교대(8 h)당 알람 건수 | ≤ 8건/교대 |
| 신뢰구간 폭 | 이상 점수의 불확실성 구간 | 폭 좁을수록 "확신" 표시 가능 |

## 11. 불확실성·유의성

- **점추정 금지.** 모든 1차 지표는 **블록 부트스트랩 95% CI**를 병기한다.
  - 블록 길이 = 200 window (= 20 s). stride 1 중첩 때문에 샘플 단위 부트스트랩은 CI를 3~4배 과소추정한다.
- **모델 간 비교**는 McNemar 검정(동일 테스트셋, 짝지은 예측)으로 한다. t-검정 금지(관측이 독립이 아님).
- **양성 이벤트 1건**이라는 한계를 보고서에 **명시**한다. 숨기면 발표평가에서 지적당하고, 먼저 쓰면 "데이터 진단을 제대로 한 팀"이 된다.
  - 완화책: 이상 구간을 시간 블록으로 쪼개 유사 이벤트 k개로 취급(+ 그 가정의 한계 명시), 또는 정상 데이터에 물리 기반 합성 결함 주입(외부데이터 규정상 출처·방법 명시 필요).

## 12. 안티패턴 체크리스트 (제출 전 최종 점검)

- [ ] Accuracy를 주요 지표로 쓰지 않았다
- [ ] F1을 보고할 때 **평가 층(L2)과 유병률(4.3%)** 을 각주로 달았다
- [ ] FPR만 쓰지 않고 FAR/h를 병기했다
- [ ] 임계값을 이상 데이터로 튜닝하지 않았다(또는 했다면 명시했다)
- [ ] window를 셔플해서 분할하지 않았다
- [ ] 결측구간을 가로지르는 window를 제거했다
- [ ] BL-0(1줄 규칙)을 넘었다
- [ ] 날짜 교란 통제 실험(E1~E3) 결과를 실었다
- [ ] 양성 이벤트 1건 한계를 명시했다
- [ ] 모든 수치가 `baseline_check.py` 류의 스크립트로 재현된다 (문항 6)

### 13.2 여기서 나오는 우선순위

1. **확률보정 + 불확실성 추정** — 단일 작업으로 **문항 2(확률 요건) + 문항 5(명시 키워드 2개)** 를 동시에 친다. 투자 대비 회수가 가장 크다.
   - 재구성오차 → 확률: Platt scaling 또는 Isotonic regression (정상 검증구간만으로 적합)
   - 불확실성: MC-Dropout 또는 딥앙상블의 예측 분산 → §9 "확신 표시"와 연결
2. **문항 3이 통째로 비어 있다** (15점). 영향변수·상호작용 분석은 §8 분해표와 별개 작업이다. 채널 ablation(§6.3 E2)을 영향변수 분석으로 승격시키면 두 문항을 함께 커버한다.
3. **문항 1의 "변수 의미"** — 가이드북 PDF에서 AI0/AI1의 상·하부 매핑을 확인해 채워 넣는다. 비용이 거의 0인데 비어 있다.
4. **"해당 없음"도 쓴다** — 설비·제품 축 부재, 불균형 학습 미적용 이유처럼 **없는 것을 근거와 함께 없다고 쓰는 것**이 침묵보다 점수가 높다.
