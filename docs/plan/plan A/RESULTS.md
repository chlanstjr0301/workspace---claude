## 1. 평가조건 고정 블록 — 보고서 제2장에 그대로 삽입

작성요령 "동일한 평가조건에서 어떤 차이가 나타났는지"에 대한 직접 답변.

```
windowing  : gap-aware. dt > 0.5 s 로 수집 구간을 끊고 구간 내부에서만 window 생성
             SEQ = 20 샘플 = 정확히 1.9 s, stride 1, offset 없음
분할       : train  정상[:12000]      6,021 window   (적합 전용)
             valid  정상[12000:15000] 1,468 window   (임계값 전용, 이상 라벨 미사용)
             test   정상[15000:]      2,489 window + 이상 전체 276 window
표준화     : 학습구간만 fit. 범위규칙·IsolationForest 는 스케일 불변이라 미적용(모델별 명시)
임계값     : 정상 검증구간 이상점수의 q99.9  — 이상 라벨을 전혀 사용하지 않음
디바운스   : k = 5 (0.5 s). 공정 상수로 사전 선언
불확실성   : burst 단위 블록 부트스트랩 95 % CI (B = 1,000)
특징       : 24개 중 AI2 유래 5개는 D1 규칙으로 제외 → 후보 특징집합 4종
후보       : 8개 검출기 × 4개 특징집합 = 32개 (D1 위반 16개는 민감도 분석 전용)
```

### D1 — 사전 선언 배제기준

> 정상 운전변화 전 구간에서 변동계수 1 % 미만으로 불변이면서 수집 세션 간에만 변하는 특징은,
> 단일 세션으로 교란 여부를 **반증할 수 없으므로** 최종모델에 포함하지 않는다.

AI2 채널 전체가 여기 해당한다 — 전원 캐리어(0.6 Hz) 파워 비중이 정상 95.9 % → 이상 10.4 %로 **겹침 없이** 갈린다. 가동 중인 모터 전류에서 기본파가 이렇게 사라지는 것은 물리적으로 불가능하므로 수집 경로 차이로 본다. 배제의 대가는 §5에 정량화했다.

| 지표 | 상태 | 근거 |
|---|---|---|
| **FAR/h** | 변별 불가 | 정상 테스트 관측 **0.139 h**. 알람 0건 → 0.0/h(95 % 상한 21.6), 1건 → 7.2/h(상한 34.2). **두 구간이 겹친다.** "FAR/h = 0" 하드 제약은 노이즈로 후보를 거르는 짓이므로 **FP 개수로 순위만** 매긴다 |
| **탐지지연** | 변별 불가 | 이상 파일 첫 burst 가 4샘플이라 window 를 만들 수 없다. t₀ 이후 첫 유효 window 까지 **8.78 s** 는 **모델과 무관한 구조적 하한**이고 전 후보가 동일하다 |
| **Event Recall** | 변별 불가 | 양성 이벤트 **1건** → 탐지에 성공한 모든 후보가 1.0 |

→ 변별 가능한 축은 **F1 의 CI 하한 / FP 개수 / 파라미터 수** 뿐이다. 선정 규칙을 이 셋으로 재작성했다.

### 그런데 1·2위는 통계적으로 구분되지 않는다

**따라서 두 모델을 역할로 나눈다** — 이 구분 자체가 선정근거의 핵심이다.

| 역할 | 모델 | 이유 |
|---|---|---|
| **판정 기준(reference)** | `S1_VIB` 범위규칙 | 파라미터 0개, 재현에 난수가 없고, 임계값 외 하이퍼파라미터가 없다. **"이보다 복잡한 모델이 정당화되려면 이것을 유의하게 이겨야 한다"**는 기준선 |

> **보고서 문장**: "성능이 통계적으로 동률인 두 후보 중, 파라미터 0개 규칙을 **판정 기준**으로 삼고 설명 가능한 MSPC 를 **운영모델**로 채택했다. 복잡도를 늘리는 선택에는 유의한 성능 근거가 없었고, 그 사실을 숨기지 않는다."

## 6. 오경보 집중조건 (문항 3 — 15점)

FP 가 가장 많은 D1 통과 후보(`S1_VIB / OCSVM`, FP=191)를 기준으로 분해.

| 구간(행) | window | FP | FP율 | AI1_std | corr01 | 진폭비 |
|---|---|---|---|---|---|---|
| 15,000–16,000 | 501 | 13 | 2.6 % | 0.0888 | +0.197 | 0.805 |
| **16,000–17,000** | 499 | **64** | **12.8 %** | **0.0434** | **−0.198** | 0.914 |
| **17,000–18,000** | 504 | **56** | **11.1 %** | **0.0418** | **−0.248** | 0.934 |
| **18,000–19,000** | 502 | **54** | **10.8 %** | 0.0581 | −0.093 | 0.870 |
| 19,000–20,000 | 483 | 4 | 0.8 % | **0.1030** | **+0.316** | 0.852 |

**16,000–19,000 구간 집중도: 174 / 191 = 91.1 %**

### 해석 — 보고서 제3장 본문

> 오경보는 정상 테스트 2,489 window 에 균등 분포하지 않는다. **91.1 %가 행 16,000–19,000(약 300 초) 단일 구간에 집중**된다. 이 구간은 진동 진폭이 0.089 → 0.042 로 **53 % 감소**하고 상·하부 진동 상관이 +0.197 → −0.248 로 **부호가 반전**되지만 `Equipment_state = 0`, 즉 **설비가 정상이라고 라벨된 운전변화**다. 행 19,000 이후 진폭 0.103 · 상관 +0.316 으로 **학습구간 수준(0.115 / +0.306)에 복귀**하므로 영구적 드리프트가 아니라 **가역적 제2 운전모드**다.
>
> 즉 출제문이 지적한 "정상적인 운전변화를 이상으로 오인"하는 조건이 데이터 내에 실존하며, 본 보고서는 이를 **오경보 집중조건 #1**로 특정한다.

### 여기서 따라 나오는 두 가지

1. **역위상은 고장 전용 서명이 아니다.** 정상 구간에서 corr01 이 −0.248 까지 내려간다. 고장을 구별하는 것은 역위상 자체가 아니라 **역위상 + 진폭 증가의 동시 발생**이다. 정상 운전변화는 역위상이면서 진폭이 **감소**하고, 고장은 역위상이면서 진폭이 **증가**한다. → `corr01 × 진폭` 상호작용 특징을 S1~S3 전 집합에 넣은 근거.
2. **최종모델이 FP=0 인 이유는 견고함이 아니라 방향**이다. 정상 운전변화가 진폭을 학습 분포 **안쪽**으로 밀고 고장은 **밖**으로 민다. 따라서 다음 한계를 반드시 쓴다.
   > "정상 운전변화가 진폭을 **증가**시키는 모드(더 큰 프레스 작업, 압력 설정 상향)가 존재하면 본 모델은 오경보를 낸다. 본 데이터에는 그런 모드가 관측되지 않았다."
