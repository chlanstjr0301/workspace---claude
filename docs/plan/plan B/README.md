## 0. 한 장 요약

**헤드 메시지: 이 데이터에서 이상을 가장 강하게 가르는 신호는 진동 진폭이 아니라 전류 파형의 시간 구조다. 다만 이 신호가 고장 때문인지 측정 조건이 바뀐 탓인지 데이터만으로는 가릴 수 없으므로, 두 가설을 모두 열어 둔 채 모델을 고르고 보고한다.**

| 질문 | Plan B의 답 | 근거 수치 |
|---|---|---|
| 무엇이 이상을 가르나 | 전류 lag-1 자기상관 | 단일 특징 AUROC **0.994**, 정상 내부 전·후반 AUROC 0.504 |
| 진폭 규칙(BL-0)으로 충분한가 | 아니다 | Recall 0.533, 블록 교차검증 오경보 **4건(7.2건/h)** |
| 오경보는 어디서 나나 | 정상 데이터 안의 저부하 구간(행 16000~17999) | 전체 특징 모델의 오경보 window 37개 중 23개 |
| 최종 후보 | 불변 특징 마할라노비스(M1) + 전류를 뺀 진동 모델(M4) 2단 판정 | M1: Recall 0.953, 블록 교차검증 오경보 0건, 섭동 후 Recall 0.953 |
| 이상 "확률"은 어떻게 내나 | 정상 기준 conformal p-value → 3단계 신호등 | 이상 데이터를 임계값 결정에 쓰지 않음 |

Plan A와의 관계: Plan A의 데이터 진단(버스트 수집, gap-aware windowing, F1 포화, 유병률 의존성)은 그대로 이어받는다. 바꾸는 것은 세 가지다. (1) 1차 지표에서 Event Recall을 빼고 블록 교차검증 오경보와 진입시점 탐지지연을 넣는다. (2) BL-0을 "넘어야 할 기준"이 아니라 "오경보를 내는 단순 규칙"으로 다시 평가한다. (3) 특징을 센서 설치 차이에 대한 민감도로 분류해 모델 선택 기준에 넣는다.

## 2. 데이터 진단 (문항 1)

### 2.1 데이터 사실

| 항목 | 정상 `press_data_normal.csv` | 이상 `press_data_outlier.csv` |
|---|---|---|
| 행 수 | 20,000 | 600 |
| 수집일 | 2022-07-12 (00:00:00 ~ 01:16:55) | 2022-07-17 (10:51:07 ~ 10:53:53) |
| `Equipment_state` | 전부 0 | 전부 1 |
| 기록 간격(연속 구간 내부) | 0.1 s (10 Hz) | 0.1 s (10 Hz) |
| 연속 구간(run) 수 / 최대 길이 | 599개 / 50샘플 | 21개 / 50샘플 |
| 공백이 차지하는 시간 비율 | 58.0 % | 65.0 % |
| 결측치 / 중복 타임스탬프 | 0 / 1건 | 0 / 0건 |

변수 의미는 가이드북 기준이다: `AI0_Vibration` 유압펌프 **상부** 진동, `AI1_Vibration` **하부** 진동, `AI2_Current` 유압펌프 전류. 가이드북이 밝힌 고장 기전은 "기어 마모 → 진동·소음 증가, 출력 유압 저하"이고, 고장이 나면 최대 2~3일 가동이 중단된다.

### 2.2 진단 결과 6가지

**(1) 이상 이벤트는 1건이다.**
이상 파일은 166초 동안 끊김 없이 이어진 기록 하나이고, 라벨은 파일 전체에 붙은 상수다. window 428개나 run 21개는 같은 고장 한 번을 잘게 나눈 조각이라 독립 표본이 아니다.
→ 다른 고장으로 일반화되는지는 이 데이터로 검증할 수 없다. 보고서에 한계로 먼저 쓴다.
→ "이상 구간 시작 시각"이 없으므로 고장보다 얼마나 앞섰는지(리드타임)는 정의할 수 없다. 대신 탐지가 얼마나 늦는지(탐지지연)를 잰다(§5.2).

**(2) 데이터는 연속 시계열이 아니라 버스트 수집이다.**
run 길이 상한이 두 파일 모두 정확히 50샘플(5 s)이므로 "5초 수집 후 대기"를 반복하는 수집 설계로 본다. 공백을 가로지르는 window는 시간 간격이 제각각인 가짜 시계열이 되므로 모두 버린다(gap-aware windowing, Plan A §1.1).

**(3) 정상과 이상은 수집일이 다르다(날짜 교란).**
정상은 7/12 자정, 이상은 7/17 오전이다. 모델이 고장이 아니라 "다른 날의 측정 조건"을 학습해도 점수가 나온다. 이를 가리기 위해 §6.4의 섭동 실험을 한다.

**(4) 10 Hz 샘플링에서는 주파수 분석을 물리적으로 해석할 수 없다.**
모터 전류는 상용 교류(60 Hz)이고 모터 회전 진동도 수십 Hz 대역이다. 10 Hz로 찍으면 나이퀴스트 주파수가 5 Hz라서 이 성분들이 모두 0~5 Hz로 접혀 들어온다(aliasing). 따라서 FFT로 "베어링·기어 결함 주파수"를 뽑는 방식은 쓰지 않는다. 쓸 수 있는 정보는 다음 세 종류다.

| 특징군 | 기호 | 예 | 센서 이득 변화 | 센서 극성 반전 |
|---|---|---|---|---|
| 진폭 | A | window 표준편차, 최대−최소 | 민감 | 불변 |
| 형태 | S | lag-1 자기상관 | **불변** | **불변** |
| 채널 관계 | R / R' | 상·하부 진동 상관 / 절댓값 상관 | R'는 불변 | R은 민감, R'는 불변 |

가이드북은 진동 신호에 절댓값을 씌워 진폭으로 바꾸는데, 이 처리는 극성 정보를 없애므로 극성 차이에는 강건하지만 R이 담은 위상 관계도 함께 버린다.

**(5) 정상 데이터 안에 운전 상태 변화가 있다.**
2000행 블록별 window 표준편차 중앙값:

| 블록(행) | AI0 | AI1 | AI2 |
|---|---|---|---|
| 0~6 (0~13999) | 0.061~0.068 | 0.090~0.139 | 87.7~102.2 |
| 7 (14000~15999) | 0.059 | 0.075 | 88.4 |
| **8 (16000~17999)** | **0.037** | **0.042** | **75.4** |
| 9 (18000~19999) | 0.056 | 0.055 | 85.1 |

블록 8은 진동이 다른 구간의 절반 수준인 저부하 구간이다. 학습 구간(행 0~11999)에는 이런 상태가 없고 테스트 구간에만 있다. 출제문이 말하는 "정상적인 운전변화"의 실제 사례이며, 오경보 분석의 중심이 된다(§8).

**(6) 가장 강한 신호는 전류의 시간 구조이고, 그 원인은 두 가설로 남는다.**

| 특징 | 정상 test 중앙값 → 이상 중앙값 | 정상 test vs 이상 AUROC | 정상 전반 vs 후반 AUROC |
|---|---|---|---|
| **S_ac1_AI2 (전류 lag-1 자기상관)** | **0.957 → −0.033** | **0.994** | 0.504 |
| S_ac1_AI0 (상부 진동) | −0.284 → 0.535 | 0.897 | 0.557 |
| S_ac1_AI1 (하부 진동) | −0.161 → 0.497 | 0.828 | 0.610 |
| A_p2p_AI0 (상부 진동 진폭) | 0.139 → 0.404 | 0.728 | 0.597 |
| R_corr01 (상·하부 상관) | −0.036 → −0.318 | 0.686 | 0.593 |
| R_abscorr01 (절댓값 상관) | −0.073 → 0.096 | 0.576 | 0.505 |

(window 10샘플 기준. 전체 12개 특징은 `precheck_output.txt` [P1])

전류 자기상관은 정상 데이터 안에서는 전혀 흔들리지 않는데(AUROC 0.504) 이상 데이터에서는 완전히 다른 값이 된다. 전류 진폭도 커졌다(|I| 99분위수 254.4 → 443.5). 이 변화의 원인은 두 가지로 설명된다.

| 가설 | 내용 | 지지하는 점 | 반박되지 않는 점 |
|---|---|---|---|
| H1 고장 | 기어 마모로 부하 토크가 맥동해 전류 파형이 변조됨 | 진폭 증가는 샘플링 시각 오차만으로는 생길 수 없음 | — |
| H2 측정 조건 | 7/17에 수집 장치의 실제 샘플링 시각이 흔들렸거나 센서 이득이 바뀜 | 기록된 타임스탬프는 두 날 모두 정확히 0.1 s 간격이라 실제 샘플링 시각 흔들림을 확인할 수 없음 | 이득 변화는 진폭 증가도 설명함 |

데이터만으로는 둘 중 하나를 기각할 수 없다. 그래서 Plan B는 두 가설을 모두 열어 두고, 각 가설에서 살아남는 모델을 따로 제시한다(§7.2).

## 3. 핵심 전략

1. **정직한 지표로 비교한다.** 이벤트 1건, 짧은 정상 관측시간(0.56 h)에서 실제로 추정 가능한 지표만 1차 지표로 쓴다(§5).
2. **이상 데이터는 평가에만 쓴다.** 학습과 임계값 결정은 정상 데이터만으로 한다. 이상 이벤트가 1건이라 임계값 결정에 쓰면 곧바로 테스트 누수가 된다.
3. **화이트박스 모델을 중심에 둔다.** 출제문이 미탐지·오경보 조건 분석을 요구하므로, 점수를 특징별 기여로 분해할 수 있는 마할라노비스 거리 모델을 주력으로 하고 블랙박스 모델은 비교군으로 둔다.
4. **특징을 센서 설치 차이에 대한 민감도로 분류하고, 강건성을 선정 기준에 넣는다.** 날짜 교란을 정면으로 다루는 장치다.
5. **두 가설(H1·H2)을 모두 보고한다.** 전류를 쓰는 주 모델과 전류를 쓰지 않는 확인 모델을 함께 두고, 두 모델의 판정이 갈릴 때 무엇을 먼저 점검할지까지 운영 절차로 제시한다.

## 4. 전처리와 검증 프로토콜

### 4.1 분할

```
학습   : normal[:12000]         정상만. 스케일러·특징 분포·모델 학습
검증   : normal[12000:15000]    정상만. 임계값(q99.9)과 conformal 보정
테스트 : normal[15000:] + outlier 전체
```

정상 테스트 구간에는 블록 8(저부하)이 들어 있다. 학습에 없던 정상 상태에서 오경보가 나는지 보는 것이 이 분할의 목적이다.

### 4.2 window 설계

| 항목 | 값 | 근거 |
|---|---|---|
| gap 기준 | 연속 샘플 간격 > 0.5 s이면 끊음 | 버스트 사이 공백은 최소 수 초 |
| window 길이 | **10샘플(1 s)**, stride 1 | 20샘플은 window의 49.9 %만 남고, 10샘플은 74.4 %가 남음(Plan A §1.1). 1 s 안에서도 lag-1 자기상관을 9쌍으로 추정할 수 있음 |
| 민감도 분석 | 5 / 10 / 20샘플 | 길이별 잔존율과 함께 보고 |

window 수: 정상 테스트 3,710개, 이상 428개(테스트 유병률 10.3 %).

### 4.3 특징 (12개)

채널별(AI0, AI1, AI2) 표준편차·최대−최소·lag-1 자기상관 9개, 상·하부 진동 상관(R), 절댓값 상관(R'), 전류 평균(O). 모두 window 안에서만 계산하고, 표준화 계수는 학습 구간에서만 구한다.

### 4.4 금지 사항

- 스케일러·표준화 계수를 전체 데이터로 계산하지 않는다.
- window를 셔플해 분할하지 않는다(stride 1 window는 인접 window와 9/10 샘플을 공유한다).
- 이상 데이터로 임계값이나 하이퍼파라미터를 정하지 않는다. 비교용으로 했다면 보고서에 명시한다.
- 공백을 가로지르는 window를 만들지 않는다.
- 테스트 결과를 본 뒤 설정을 바꿨다면 바꾼 내용과 이유를 기록한다.

## 5. 지표 체계

### 5.1 왜 Plan A의 1차 지표를 바꾸나

| Plan A 1차 지표 | 이 데이터에서의 문제 |
|---|---|
| Event Recall | 이벤트가 1건이라 0 또는 1만 나온다. BL-0도 1.0이다. |
| FAR/h ≤ 1건/h | 정상 전체 0.556 h에서 오경보 0건이어도 95 % 상한이 6.6건/h다. "1건/h 이하"는 원리상 보일 수 없다. |
| 리드타임 | 이상 이전 구간이 없어 "고장보다 앞선 시간"을 잴 수 없다. 실제로 재는 것은 탐지지연이다. |

### 5.2 1차 지표

| # | 지표 | 정의 | 왜 이 지표인가 |
|---|---|---|---|
| P1 | **window Recall** | 정상 검증 q99.9 임계값에서 이상 window 탐지율 | 임계값을 정상 데이터만으로 정하므로 모델 간 같은 기준 |

2. 남은 모델 중 P2 블록 교차검증 오경보가 가장 적은 모델.
3. 동률이면 P1 Recall이 높은 모델.
4. 그래도 동률이면 파라미터가 적은 모델.

## 7. 최종모델과 확률 출력

### 7.1 이상 확률: conformal p-value

문항 2는 "이상 **확률**"을 요구한다. 이상 데이터를 보정에 쓰면 누수가 되므로 정상 검증 데이터만 쓰는 conformal p-value를 출력한다.

```
p(x) = (1 + #{정상 검증 window 중 점수 ≥ s(x)}) / (1 + N_valid)
```

- 뜻: "정상 설비라면 이만큼 이상한 점수가 나올 확률". 정상 데이터가 교환 가능하다는 가정 아래 p ≤ α로 알람을 울리면 오경보율이 α 이하로 보장된다.
- "이상일 확률"(사후확률)로 바꾸려면 현장 고장률 가정이 필요하다. 보고서에는 가정 고장률 1 %·0.1 %에서의 환산값을 민감도로만 싣는다.
- 비교용으로 이상 데이터를 쓴 Platt 보정 결과를 부록에 싣고, 누수가 있다는 점을 명시한다.

### 7.2 2단 판정 (최종모델 F)

| 단계 | 모델 | 쓰는 정보 | 역할 |
|---|---|---|---|
| 1단 | M1 불변 특징 | 진동·전류 형태, 절댓값 상관 | 탐지. 센서 이득·극성 차이에 영향받지 않음 |
| 2단 | M4 진동만 | 전류 제외 | 1단 알람의 확인. 진동에서도 이상이면 확신도를 올림 |

| 1단 | 2단 | 신호등 | 현장 조치 |
|---|---|---|---|
| p > 0.01 | — | 정상(초록) | 없음 |
| p ≤ 0.01 | p > 0.01 | 주의(노랑) | 계측 장치(샘플링·센서) 확인 후 교대 내 육안 점검 |
| p ≤ 0.01 | p ≤ 0.01 | 정지 검토(빨강) | 즉시 점검, 생산 일정 조정 |

이 구조는 H1·H2 어느 쪽이 맞아도 쓸 수 있다. H2라면 노랑 알람의 첫 조치(계측 장치 점검)에서 원인이 걸러지고, H1이라면 노랑 단계에서 이미 고장 징후를 잡는다. 임계값 0.01은 예비값이며, §5.2 P2와 교대당 알람 예산(§9)을 보고 확정한다.

M1 Recall(0.953)은 전류 형태 특징에 크게 기대고 있다(§8.1). 사전실험의 이상 기록에서 M4 단독 Recall은 0.584이므로 빨강 판정은 노랑보다 드물게 나온다. 이 비율이 현장 조치 부담과 맞는지는 2단 판정의 window·run 단위 결과로 확인한다(10/6 예정).

## 8. 영향요인 및 오류분석 (문항 3)

### 8.1 영향요인: 특징군 ablation

| 특징군 (마할라노비스) | Recall | FPR | AUROC | 정상 test 오경보 window 위치 (블록 7 / 8 / 9) |
|---|---|---|---|---|
| 전체 특징 | 0.998 | 1.00 % | 1.000 | 1 / **23** / 13 |
| 형태 3채널 + R' | 0.953 | 2.35 % | 0.993 | 13 / **51** / 23 |
| 전류 형태만 | 0.963 | 4.15 % | 0.993 | 20 / **98** / 36 |
| 진동만 A + S + R' | 0.584 | 0.00 % | 0.877 | 0 / 0 / 0 |
| 진동 형태만 S + R' | 0.154 | 2.08 % | 0.699 | 12 / **47** / 18 |

결론:
- **탐지력의 대부분은 전류 형태 한 개에서 나온다.** 전류 형태만으로 Recall 0.963이고, 전류를 빼면 0.584로 떨어진다. 보고서에서 이 의존성을 숨기지 않는다.
- **진폭과 형태는 서로 보완한다.** 진동 형태만 쓰면 오경보가 많고(블록 8에 47개), 진폭을 더하면 오경보가 0이 된다. 진폭 특징이 "저부하라서 형태가 흔들리는 상황"을 정상으로 되돌려 주는 상호작용으로 해석한다. 이 상호작용은 부하 수준 × 형태 특징 2차원 그림으로 보인다.
- 다음 단계: 마할라노비스 점수를 특징별 기여로 분해해 window마다 어떤 특징이 알람을 일으켰는지 표로 만든다.

### 8.2 FN/FP 집중 조건

조건 축(라벨이 없으므로 신호에서 만든다):

| 축 | 정의 |
|---|---|
| 부하 수준 | window 진동 표준편차 3분위(저·중·고) |
| 전환 구간 | 직전 window 대비 표준편차 변화율 상위 10 % |
| run 내 위치 | run 시작 후 첫 1 s / 그 이후 |
| 블록 | 2000행 단위 |

현재까지 확인한 사실과 보고서 문장 형태:
> "오경보 window 37개 중 23개(62 %)가 블록 8(행 16000~17999)에 몰렸다. 이 구간은 상부 진동 표준편차 중앙값이 0.037로 다른 구간(0.056~0.068)의 절반 수준인 저부하 구간이며, 학습 구간에는 이런 운전 상태가 없었다. 학습 구간에 없던 정상 운전 상태가 오경보의 주된 원인이다."

조치안과 검증:
- 부하 수준별 조건부 임계값을 두는 방안(부하 저 구간에서는 q99.9 대신 해당 구간 분포로 임계값을 정함)과, 블록 교차검증으로 저부하 상태를 학습에 넣는 방안을 비교한다.
- FN은 이상 run 21개 중 어느 run에서 나는지, run 시작 직후인지를 표로 만든다. BL-0과 M3는 끝까지 못 잡는 시작점이 2개씩 있으므로, 그 run의 특징값을 직접 본다.

| 운전 상태 등록 | 저부하처럼 새 운전 상태가 확인되면 정상 데이터에 추가해 재학습 | 재학습 주기는 월 1회 제안 |
| 관측 확대 제안 | 현재 정상 관측 0.556 h로는 오경보율을 시간당 6.6건 미만으로만 보장 가능. 시간당 1건 보장에는 오경보 0건 기준 정상 관측 약 3.7 h가 필요 | Poisson 상한 역산 |

비용 근거: 가이드북에 따르면 고장 시 최대 2~3일 가동 중단이 생긴다. 미탐지 1건의 비용이 오경보 1건(점검 공수)보다 훨씬 크므로, 노랑 단계는 민감하게, 빨강 단계는 보수적으로 두는 비대칭 설계를 쓴다.
